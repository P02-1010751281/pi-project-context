### 2. New findings

**R5-I1 — IMPORTANT (new regression introduced by the R4-L2 fix; blocks commit)**
`extensions/project-context/memory/sections.ts:164` — the narrowed `TAG_LINE_RE` only accepts `[A-Za-z][A-Za-z0-9-]*`, so wrapper tags whose names contain `_`, `:` or `.` (`<foo_bar>`, `<ns:memory>`, `<my.tag>`) are no longer structural. A body-less skeleton wrapped in one is now “content”, re-opening the exact silent-data-loss class R3-I2/R4-I1 closed.
- Evidence (`/tmp/rev25-probe/probes/e2e-probe.mjs`): plain path overwrote `# Project Memory\n\n## Project\n- keep me.` with the 81-byte skeleton and toasted `Project memory and context updated.`; condense path (`maxMemoryChars: 4000`) discarded the first 200-bullet real result and adopted a 65–71-byte skeleton (`seen=2`).
- Differential (`/tmp/pi-context-rev24` copy, old `TAG_LINE_RE = /^<\/?[A-Za-z][^>]*>$/` at rev24 `:163`): those three wrappers are refused in both paths there and the 4024-char first result is kept. So this is new in round 4. `<_x>`, `<1memory>`, `<记忆>` were bypasses already in rev24 (pre-existing, not caused by this fix).
- It also contradicts the code’s own JSDoc (`sections.ts:184-195`: “a wrapper tag … a skeleton wrapped in one still reads as a skeleton”) and design D7 `:158` (“独立 HTML·XML 标签”).
- Fix boundary: allow XML NameChars in the tag-name class, e.g. `/^<\/?[A-Za-z][A-Za-z0-9._:-]*(?:\s[^>]*)?\/?>$/` — `<https://…>` still fails (`:` then `/` cannot continue the name or satisfy the attribute/`>` tail), while `<foo_bar>`/`<ns:memory>`/`<my.tag>` match. Pin one plain and one condense e2e case.

**R5-L1 — LOW (residual of R4-L1): fence parity is family-blind and decoration-blind**
`sections.ts:218-224` toggles `fenced` on any `FENCE_LINE_RE` line, including a different fence family and lines that only become fences after `canonicalLine`. Falsified (`unit-probe.mjs`, `adversarial-probe.mjs`):
- `# Project Memory\n## Project\n~~~\n```\nreal fact must hold\n===\n~~~` → refused: the ```` ``` ```` line flips `fenced=false`, so `===` eats the only body line, though the only opened fence is `~~~`.
- Same with `> ``` ` / `- ``` ` inside a ``` block (canonicalLine strips the decoration, flips parity).
Impact: fail-safe false refusal + false “carried no entries” diagnostic; not new vs rev23 (unconditional consumption also refused it), but R4-L1’s stated boundary (“=== inside an odd fence count”) is not fully met. Fix boundary: remember the opening fence family and toggle only on a matching line, or skip setext consumption while any fence is open unless a same-family closer was seen; otherwise record the mixed-family boundary. The added test pins only the single-family case.

**R5-N1 — NIT (documentation): the design wording claimed for R4-N2 (and the D7 record claimed for R4-L2) is missing**
`implementation-note.md:189` claims the design now says the criterion “去掉结构行后还剩不剩带字词的行”; `structured-consolidation-output-design.md:156-160` contains no such sentence, and `implementation-note.md:187`’s “按 D7 记录为边界” for the R4-L2 narrowing is absent too. Impact: the same “claimed but not done” audit gap as the round-4 vacuous test, and the design now disagrees with the code about XML tags. Fix: add both boundaries (HTML heading vs element-with-text; actual tag-name shape) to decision 6/D7, or correct the note.
