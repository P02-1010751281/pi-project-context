## Findings (new this round)

### F1 — suggestion — Autolearn's tools-rejected fallback and failure accounting are inherited only by cross-reference
- Where: design 决策 7 lines 195–198 vs 决策 2 lines 79–84; `extensions/project-context/autolearn/pass.ts:92-102`.
- Evidence: decision 2 pins the trigger ("only the first tools call that throws falls back once, sticky afterwards") **and** "`noteModelFailure` only once after both attempts"; decision 7 says only "重试/后续调用保持旧文本 JSON 形状（fail-open），与决策 2/3 的粘性回退一致" and "`noteModelSuccess`/`noteModelFailure` 语义不变". Autolearn's `call` closure records one success/failure per invocation.
- Impact: an implementer could (a) omit the no-tools fallback, so autolearn regresses to failing closed on routes that reject `tools` (today it works everywhere), or (b) count both the tools-reject and the retry failure, burning 2 of `AUTO_DISABLE_AFTER=5` consecutive failures per pass (call-policy.ts:23,87-90).
- Minimal fix boundary: one sentence in 决策 7: "autolearn 的 tools-拒绝回退沿用决策 2 的触发与 `noteModelFailure` 单次计数（同一个 wrapper 包住两次尝试）".

### F2 — nit — `parseDecision`'s input for tool-call arguments is not pinned

### F3 — nit — The pinned item truncation is not surrogate-safe
- Where: design 决策 4 line 118; precedent `document.ts:74-82` (`clipToLineBoundary` / `isHighSurrogate`), `context-doc.ts:30-33`.
- Evidence: `itemCap_s` pin says "把条目截到 `itemCap_s`" with no boundary rule. A naive `slice(0, itemCap_s)` can end on a lone high surrogate (emoji/CJK-ext at the cut); the existing CONTEXT renderer explicitly uses a surrogate-safe clipper.
- Impact: rare invalid UTF-16 in `MEMORY.md`; cap invariant is unaffected (code units still counted).
- Minimal fix boundary: one clause: "用现有 `clipToLineBoundary`（或 isHighSurrogate 回退）截断".

## 决策 7 verdict: **sound** (with two small gaps that do not change contracts)

Everything the task asked to verify reproduces against the installed pi-ai (0.99.2) and the code:

- **"Only two JSON consumers" is true.** `grep` across the extension: `completeWithMeta` only in `memory/pass.ts`; `completeText` only in `autolearn/pass.ts`; `parseJsonObject` only in `memory/parse.ts` + `autolearn/parse.ts`; `handoff/run.ts` imports only `resolveAuxModel` (`:10`, used at `:32/:40/:75/:322`) and uses pi's built-in summarizer. `grep registerTool extensions/` is empty.
- **Current autolearn shape is nullable and strict-hostile — both probes reproduce:**
  - (a) required `anyOf:[{object},{null}]` → `makeStrictJsonSchema(schema, () => false)` throws `UnsupportedStrictJsonSchemaError: object and array unions are unsupported`.
  - (b) optional `type:"object"` → **NO THROW**, output is `skill: {"anyOf":[{"type":"object",...,"additionalProperties":false},{"type":"null"}]}` with `root.required` forced to `["skill","inspect"]` — an object union sent to the provider, silently violating the strict subset. The design's `:100`/`:104` citations are right (`:100` wraps; `:103` forces required).
- **Proposed always-object shape passes**: `makeStrictJsonSchema(newAutolearnShape, () => false)` → `NO THROW`; `root.required=["skill","inspect"]`, `skill.required` = all six fields, `additionalProperties:false` at both levels, `"anyOf"` absent. `record_memory` draft likewise passes with no `anyOf`.
- **Decision rule and admission rules are consistent**: `parseDecision` already maps `skill:null`/missing → `{skill:null, inspect}` (`parse.ts:16-17`) and object → propose (`:20-33`); `collectEvidence` slices to `AUTOLEARN_INSPECT_SESSIONS=4` and only archived ids (`evidence.ts:11,48,105-107`); `rejectionReason`/`shapeRejection` untouched (`candidate.ts:29-58`). The old shape `{"skill":null}` → none is preserved. One intentional behavior delta: a skill object with empty name now maps to none/inspect instead of reaching `rejectionReason("invalid kebab-case name")`; that is inherent to `name:""` = no-skill.
- **B2 is stated and technically sufficient**: `completeText` discards `stopReason` (`llm.ts:118-124`), the design switches autolearn to `completeWithMeta` (design lines 195, 198, 263) and mandates one no-tools retry; `completeWithMeta` already returns `stopReason`, and `parseStreamingJson` repairs truncated arguments (`json-parse.js:90-107`). Gaps are F1 (tools-rejected fallback inherited by reference) and F2 (parse input), not the length retry itself.
- **Not scope creep**: folding autolearn in is owner-sanctioned (Q5), stays within "output shape + parse" plus the required B2 truncation retry, and does not touch throttling/candidate lifecycle/admission rules (`autolearn/skill.ts`, `candidate.ts` unchanged; 非目标 line 332). It is justified by the shared `llm.ts` failure contract, which the consolidation work changes anyway.
