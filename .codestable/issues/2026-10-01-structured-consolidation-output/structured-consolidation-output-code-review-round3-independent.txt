## 4. New findings

### R3-I1 — IMPORTANT (regression, fail-safe): the fence strip crosses non-`\n` line boundaries
`extensions/project-context/memory/sections.ts:173`

```ts
.replace(/^[^\S\n]*(?:```|~~~)[^\n]*$/gm, "")
```

`[^\n]*` can swallow `\r`, U+2028 and U+2029, and because the end-of-string `$` satisfies the match first, a document whose first physical line is a fence and which uses lone CR/LS/PS separators loses **everything after the opening fence**. Impact: a content-bearing opaque reply is classified `semanticEmpty`, the write is skipped, and `report.ts:380` / `pass.ts:292` claim "the reply carried no entries" (false). E2E (`/tmp/probe-r3/regression.mjs`, `cr-fence.mjs`): CR-only, U+2028- and U+2029-joined fenced real memories (>40 chars) were all **REFUSED** with that false diagnostic; the LF control wrote. The old R2 predicate (reconstructed from the round-2 transcript) classified the CR/LS versions as content, so this is a regression introduced by the new fence strip. The JSDoc at `sections.ts:161-163` even claims "Line terminators are normalized first", but the replaces run before the split. Fix boundary: use `[^\r\n\u2028\u2029]` in the fence matcher (and optionally `[^\S\r\n\u2028\u2029]` in the thematic matcher), or actually normalize line endings before the replaces; pin one CR/LS + fence case unit and e2e. The existing CR case (`tests/sections-test.mjs:283`) starts with `#`, so it never catches this.

### R3-I2 — IMPORTANT residual (design-sanctioned boundary): text-bearing skeletons are still "content"
`extensions/project-context/memory/sections.ts:179-182`; condense branch `pass.ts:260-268`

The rule is "not an ATX heading **and** holds a letter/digit", so any wrapper line defeats it. E2E (`/tmp/probe-r3/decorated.mjs`): preamble + skeleton, `<memory>`-wrapped, HTML-heading, numbered-heading and bullet/ZWSP-prefixed skeletons all **overwrote** real memory and toasted "Project memory and context updated."; the plain skeleton is correctly blocked. Worse, the condense branch adopts a decorated skeleton: first reply a ~4800-char real opaque memory over the 4000 cap, condense reply `- # Project Memory\n- ## Project…` → stored file 91 bytes of skeleton, first real result discarded, toast "updated" (`/tmp/probe-r3/condense.mjs`). This matches the recorded D7 loose rule, so it is not a code/design mismatch; but it is the same silent-replacement class R1/R2 blocked, reached through decorations. Fix boundary: either record the residual in decision 6/D7 (wrappers are accepted as content) or normalize each line before the ATX test (strip bullet/blockquote prefixes and zero-width chars; treat the normalized ATX as heading), and add a condense-branch case whose condensed reply is a decorated skeleton. `#######Project` (no space) is newly content vs. the R2 predicate, as the trade-off that keeps `#1 rule` content — intended, but worth a D7 sentence.

### R3-N1 — NIT: the kept-memory reply generalizes the semantic-empty wording
`extensions/project-context/memory/report.ts:380` (and comment `:25-26`)

```ts
return `Project context updated; project memory was kept unchanged (the reply carried no entries).${clippedNote}${guard}`;
```

For the opaque `< 40` skip the reply did carry text (`Short note.`), so "carried no entries" is false. Fix: branch the parenthetical on `outcome.semanticEmpty` (e.g. "the reply was empty or too short to be a change"); update the `memoryKept` comment accordingly.
