## 2. New findings

### R4-I1 — IMPORTANT (residual of R3-I2): the invisible-character set is incomplete; the R3-I2 data-loss path is still reachable
`extensions/project-context/memory/sections.ts:155` — `ZERO_WIDTH_RE = /[\u00ad\u200b-\u200d\u2060\ufeff]/g` covers only part of Unicode `Cf`. U+200E LRM, U+200F RLM, U+202A–202E bidi controls, U+2061–2064 invisible operators, U+2066–2069 isolates, U+180E, U+061C are not stripped. Because `canonicalLine` runs before the ATX test, a skeleton prefixed with one of them stays "content".

Verified E2E (`/tmp/probe-r4/tests/rlm-condense.mjs`):
- plain path: `\u200e# Project Memory\n\u200e## Project…` **overwrote** a real stored memory and toasted `"Project memory and context updated."`;
- condense path: the first ~4 800-char real result was discarded, the stored file was an **86-byte** RLM-prefixed skeleton, toast `updated`.

Impact: same silent data loss as R3-I2, on a different invisible prefix. Fix boundary: `ZERO_WIDTH_RE = /\p{Cf}/gu` (safe — stripping `Cf` can only move a line toward structural, never toward content), or enumerate the missing code points; pin one plain and one condense case. If the owner prefers to record rather than close, D7 must say "only the listed `Cf` characters are stripped; any other invisible prefix is content".

### R4-L1 — LOW (new false refusal): the `===` setext rule ignores fence context
`extensions/project-context/memory/sections.ts:213` — `lines.forEach(… if (index > 0 && /^=+$/.test(line)) structural[index - 1] = true)` has no fence-parity state. `# Project Memory\n## Project\n```\nvalue\n===\n```` judged heading-only → write refused; rev23's predicate judged it content. The code block has a body; the setext underline eats its only real line. Fix boundary: skip the line-above consumption when the `===` line sits inside an odd fence count (or record the case).

### R4-L2 — LOW (new false refusals): lone tag / autolink / HTML-heading body
`extensions/project-context/memory/sections.ts:163-164` — `TAG_LINE_RE` also matches a lone generic `<T>` and an autolink `<https://x.example>`, and `HTML_HEADING_LINE_RE` matches `<h2>Overview</h2>`. If that line is the only non-structural line, the whole reply is refused (rev23 wrote it). A plain URL-only line and path-only line still pass. Impact: rare opaque memories that consist of exactly one tag/autolink/HTML-heading line lose their write with the false "carried no entries" diagnostic. Fix boundary: narrow the tag matcher to wrapper tags, or record the boundary (the `<hN>…</hN>` part is deliberate per D7).
