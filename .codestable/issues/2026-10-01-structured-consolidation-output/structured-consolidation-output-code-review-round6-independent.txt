### 2. New findings

**F1 — LOW (pre-existing; data-loss shape) — `TAG_SPAN_RE` is quote-unaware, so a wrapper with `>` inside an attribute still strips dirty**
`memory/sections.ts:166` `const TAG_SPAN_RE = /<[^>]*>/g;`. `<x title="a>b">` leaves `b">` after stripping, so `isTagOnlyLine` is false and a body-less skeleton wrapped in it is "content".
- E2E (`/tmp/rev26-probe/probes/r6-bypass-e2e.mjs`): plain path overwrote `# Project Memory\n\n## Project\n- keep me.` with the 67-byte skeleton and toasted `Project memory and context updated.`; condense path discarded the 4024-char first result and adopted the 67-byte skeleton (`seen=2`).
- Cross-revision probe (`r6-crossrev.mjs`): same result in rev24 and rev25 — **not introduced by the R5 fix**.
- Trigger plausibility: `grep` over `.agents/memory` finds **0** tags with `key="value"` attributes from the model; wrappers in the corpus are plain `<memory>`/`<existing-memory>`-style names. Unclosed `<memory` (malformed) is the same class.
- Fix boundary if the owner wants zero known fail-open markup-only edges: `/<(?:[^>"']|"[^"]*"|'[^']*')*>/g` (quote-aware span). Otherwise this is the same accepted-boundary family as decision 6/D7:161.

**F2 — LOW (pre-existing; fail-safe) — fence parity ignores opener length and info strings**
`sections.ts:161` `FENCE_LINE_RE` captures only the family; `:231-238` closes on any same-family line.
- `# Project Memory\n## Project\n```\n```js\nreal fact must hold\n===\n```\n` → `isHeadingOnlyDocument` = `true` (refused) even though the only real body line is inside the block. Same for a 4-backtick opener closed by a 3-backtick line, and the `~~~` variants (`r6-fence.mjs`).
- Impact: fail-safe false refusal + the false `the reply carried no entries` toast/diagnostic; condense keeps the first result. Pre-existing in rev24/rev25 (cross-revision table).
- Fix boundary: track `{char, length}` of the opener and close only on same char, run length ≥ opener, no info text (or record the boundary).

**F3 — NIT (pre-existing; fail-safe) — decorated `===` still eats the line above**
`sections.ts:238` tests the *canonical* line, so `real fact must hold\n- ===\n` (also `> ===`, `1. ===`) marks the real line structural → refused. In markdown those are bullets/quotes, not setext underlines. Fix: test the raw trimmed line (`raw[index]`) for `/^=+$/`. Contrived input; recorded for completeness.

**F4 — LOW (behavior changed by the R5 fix relative to rev25; fail-safe) — `AUTOLINK_RE` shape is narrower than "autolink"**
`sections.ts:165` admits only `scheme://…` and lowercase `mailto:`. `<user@example.com>`, `<MAILTO:…>`, `<tel:+15551234>`, `<urn:…>` are markup-only → refused. Cross-revision: rev24 `true`, rev25 `false`, rev26 `true` — i.e. the round-5 general rule re-classified these as structural.
- E2E (`r6-refusal-e2e.mjs`): plain path kept the memory but toasted `…memory was kept unchanged (the reply carried no entries)` for `<img alt="the architecture diagram with the full legend of every module">` — a false statement; condense kept the first result.
- Fix boundary: add an email-shaped alternative (bare `local@domain`); do **not** broaden to every `scheme:` shape, because CommonMark-style `<ns:memory>` would then be an autolink and content again — re-opening R5-I1. CDATA-with-words and comment-with-words are refused by the same stripping (fail-safe, no fix needed).
