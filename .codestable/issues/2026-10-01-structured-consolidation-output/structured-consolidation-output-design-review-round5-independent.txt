## Findings

### F5-1 — important (data-loss variant of F4-1) — the new semantic-empty gate is bypassable by a schema-legal reply
- Where: design 决策 6 lines 133–137, 条目卫生 lines 108/195; schema draft lines 156–159; code `report.ts:73`.
- Evidence: the schema is `items: {type:"string"}` with no `minLength`, and `makeStrictJsonSchema` only forces `required`/`additionalProperties` (`constrained-sampling.js:101–112`). So `{memory:{project:[""],invariants:[],pitfalls:[],index:[]}}` + a valid context is schema-legal and strict-legal. The gate is phrased as “四个节全空” but never defines 空 after entry normalization; hygiene only covers newlines / `## ` / marker shapes. With `project:[""]` the array is non-empty, the renderer emits headings plus a blank bullet (>40 chars), `report.ts:73` sets `memoryChanged=true`, and `recordMemoryDocument` replaces MEMORY.md. On this repo the old side is unparseable (`## Documentation and review conventions`), so 决策 5 skips the guard silently — the F4-1 wipe shape survives with a slightly odd reply.
- Impact: “语义空回复绝不写盘” is not airtight; a legal “nothing to say” quirk (`[""]` / `[" "]`) still wipes memory.
- Minimal fix boundary: define section-emptiness on the *normalized* entries (trim; drop entries that normalize to empty) and compute `semanticEmpty` on that view; add a test with `[""]`/`[" "]`.

### F5-2 — important — F4-5 is not actually fixed: adjacent bullets still split ownership of the name check
- Where: design lines 190–192.
- Evidence: line 191 says llm.ts suppresses name-agnostically and returns all extracted `toolCalls`; line 192 (untouched by the delta) says suppression requires “name 匹配 `record_memory` **且** arguments 非 null 对象”, i.e. llm.ts owns the memory-specific name. The rev12→rev13 diff shows only the new bullet was inserted; the old one remains verbatim.
- Impact: the implementer cannot satisfy both; N9/F4-5 is still unresolved, and “present but unusable” observability depends on which reading wins.
- Minimal fix boundary: delete the name clause from line 192; suppress in llm.ts on any usable `toolCall` (non-null object args, name-agnostic), return every extracted call (including unusable) so pass.ts can observe, and let pass.ts throw on name-mismatch + empty text.

### F5-3 — important — the renderer is still described with two contracts (F4-3 residual)
- Where: design line 116 vs lines 193/202 (also line 109).
- Evidence: line 116 pins `renderMemoryDocument(sections, cap) → { text, sectionDropped, itemTruncated, neededChars }` and says “不再叫裸 `dropped`”; 接口改动 line 193 still says `renderMemoryDocument(sections, cap) → { text, dropped }` and line 202 says “`pass.ts` 把 `dropped` 传到这里作为 cap 事件”. Line 109 also still uses `dropped`.
- Impact: the doc contradicts itself on the exact contract F4-3 asked to pin; an implementer following 接口改动 misses the carriers and the cap-event distinction.
- Minimal fix boundary: update lines 193/202 (and the wording at 109) to the pinned shape/field names.

### F5-4 — important — the condense adoption predicate is still undecided (7-decision #5)
- Where: design lines 112–115.
- Evidence: triggers are pinned (structured/parsable: `sectionDropped>0`; opaque: `exceedsMemoryCap`), but nothing says what may be adopted after the condense call. Current code adopts only `condensed && !exceedsMemoryCap(condensed.memory, limit)` (`pass.ts:142`); under the section renderer the condensed output is always rendered ≤ cap, so that predicate no longer discriminates, and an unparseable condensed reply can silently switch the write to the opaque legacy path.
- Impact: implementer must invent the acceptance rule; a wrong choice can replace the first result with a worse or differently-clipped one.
- Minimal fix boundary: pin it, e.g. adopt iff the condensed reply parses (tool-call / `sectionsFromMarkdown`) and its own `sectionDropped == 0`; if unparseable or still dropping, keep the first result and log/warn per kind.

### F5-5 — important — gated-pass reporting and the fallback placeholder are unpinned
- Where: design lines 135–136/140; code `report.ts:75`, `:139`, `:159`; `context-doc.ts:84`.
- Evidence: with `semanticEmpty` forcing `memoryChanged=false` but a usable context, `update` is truthy → `report.ts:139` returns “updated”/“clipped” and `report.ts:159` notifies “Project memory updated: …” (commands reply “Project memory and context updated.”), although memory was deliberately not written. With all-empty + no usable context and no existing CONTEXT.md, `report.ts:75` still builds `fallbackUpdate(ctx)` → a placeholder CONTEXT.md is written and the pass reports “updated”, contradicting line 135’s “整个 pass 报 `unchanged`”.
- Impact: the new gate state produces false “memory updated” claims, and the stated test “全空 + 无 context → unchanged” can fail on a project without CONTEXT.md.
- Minimal fix boundary: say whether the gate also suppresses `fallbackUpdate` (or narrow the “unchanged” wording), and specify gate-aware notify/reply wording (“context updated; memory kept”).

### F5-6 — nit — `neededChars` expression lacks a ceiling (F4-4 residual)
- Where: design line 111.
- Evidence (probe): O = 76; share 0.15, `content_s=590` → expression = 4009.33. At cap 4009 the budget is `floor((4009-76)*0.15)=589 < 590` (still clips); at 4010 it is 590. `/project-context max-memory` does `Math.round(chars)` (`index.ts:145`), so copying 4009.33 sets 4009 and silently under-delivers. The stated 20000/0.4 case (50076) happens to be integral and correct.
- Impact: the “minimal cap that stops the clipping” advice can still clip.
- Minimal fix boundary: state `Math.ceil` (ratio before adding overhead) and the behavior above `MAX_MEMORY_CHARS_LIMIT`, or drop the number and keep the qualitative warning (line 111 already allows this).

### F5-7 — nit — stale/wrong citations
- Where: design line 132 (`report.ts:84`) — the `update = outcome.result.context ?? …` line is `report.ts:75` (verified in rev12 and rev13); design line 71 (`constrained-sampling.js:180`) — :180 is the `makeStrictJsonSchema` call, while the unsupported-strict throw is :192 (as line 39 correctly says) and the keyword rethrow is :188; line 132 says “实测 66 字符” — the rendered skeleton is 67 raw / 66 trimmed.
- Impact: readers following the numbers land on unrelated code; line 39 and line 71 contradict each other.
- Minimal fix boundary: correct the three numbers.

### F5-8 — nit — guard ownership/placement wording
- Where: design line 138 vs line 121.
- Evidence: 决策 5 puts the comparison pre-render (naturally in pass.ts, which holds old `loadMemory` and the adopted sections); 决策 6 says “`report.ts` … 跳过回归守卫”. `report.ts` cannot skip a comparison it doesn’t run.
- Impact: the module boundary for the guard and its suppression is ambiguous.
- Minimal fix boundary: state that pass.ts skips the guard when `semanticEmpty` (and emits the F4-7 diagnostic), carrying the flags/counts to report.ts only for `memoryChanged` and wording.

### F5-9 — nit — the F4-7 diagnostic has no test and no pinned emitter
- Where: design line 140; tests lines 232/236.
- Evidence: the two N1 tests only assert byte-invariance and absence of “移除 N 条”; nothing asserts the plain `errors.log` diagnostic, and the doc doesn’t say whether pass.ts or report.ts writes it.
- Minimal fix boundary: name the emitter and add a test for gated + non-empty old memory (plain diagnostic, not a warning toast).

### F5-10 — suggestion — prefer the “no numeric advice” branch
- Design line 111 allows either. Given the share/ceil/clamp interactions (F5-6) and that the cap event + `kind` already carry the cause, dropping the number removes an entire class of mis-advice.

Only two local deepseek models declare `supportsStrictMode` (probe: `deepseek/deepseek-flash`, `deepseek/deepseek-v4-pro`); the shipped shape guarantee is function-calling semantics, not grammar.
