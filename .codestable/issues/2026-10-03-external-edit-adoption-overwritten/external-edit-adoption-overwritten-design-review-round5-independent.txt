## important

**IM-1 §9 class 1 谓词过宽：`!memoryChanged` notify 与 `contextShapeWarned` 被错误归入"memory 发布"，字面执行会回归 design 自己声明要保护的既有组合。**
- `file:line`：`design:201-206`（class 1 含 `:232-259` 全块、`:138/:145`）；`report.ts:232-237`（`!memoryChanged` toast）、`:135-151`（contextShapeWarned 消费）、`:202-203`（"context rewritten while memory kept"注释）、`:217-226`。
- 影响：`memoryChanged===false`（heading-only/opaque<40）时 `recordMemoryDocument` **根本不会被调用**，按 `design:205-206` 的字面写法它也是 `written:false` 的 attempt ⇒ ①今天必发的 toast `Project context updated; project memory was kept unchanged`（probe 输出 `["info:Project context updated; project memory was kept unchanged."]`）消失；②`contextShapeWarned` 永不消费/永不落日志——对"模型长期只回四标题骨架 + context 形状漂移"的稳态，今天的 once-per-process 日志被永久压掉（probe 两 fixture 今天均落 `carried a context section that could not be used`）。注意这与"回复被丢弃"无关：这条路径的 context 会被写入/保留，回复并未被丢弃，`design:203-204` 给出的豁免理由（"回复被丢弃时不该烧掉"）不适用。
- 修复边界：class 1 只保留"描述 memory 发布"的分支（`storedPoisoned`/`cappedSections`/`cappedMemory`/`clipped`/`updated` 五个 notify 分支与三类 errors.log）；`!memoryChanged` toast 保持今天行为；`contextShapeWarned` 的门改为"该 attempt 被 superseded/回复被丢弃"，非 stale 的 no-write 路径照旧消费。

**IM-2 class 1 清单漏 `report.ts:228-230` 的 clipped errors.log。**
- `file:line`：`design:202-203`（清单）；`report.ts:228-230`。
- 影响：条件 `outcome.clipped && (memoryChanged || update)` 在"最终 attempt 陈旧（`written:false`）但 memoryChanged===true、update===undefined"时仍成立 ⇒ 写出 `consolidation shortened the existing memory or context…`——关于一次并未发生的发布的 errors.log。这正是 R4-IM-1 要消灭的日志类，且 §8 row 5/6 与 INV-3 都要求该路径不得有发布侧后果。触发需要 clipped prompt + stale，窄但确定。

**IM-3 T9 的验收线与 §9 class 2 直接矛盾，且 pass 侧 removal 日志使其在自然 fixture 下不可满足。**

## learning

- **"written:true"不是"回复未被丢弃"的充分谓词**：`memoryChanged===false` 是一条**既有的 no-write 路径**，在这条路径上 CONTEXT 可写、回复并未被丢弃。门控应按"决策状态"（published / superseded-discarded / no-write-as-before）三态，而不是按写结果两态。
- step 8 的**字节谓词顺带关闭了 R-1 的窗口变体**：mtime 被回拨（`cp -p`）的编辑若落在 step 1 之后，step 8 仍以 `nowKey !== renderKey` 检出并 append；R-1 只覆盖"编辑早于 pass 读取"的 mtime 回拨。这里"读自己的字节"比读有效内容强的第二层价值，值得写进 §6 要点。
- `kept`/`adopted` 都是规范化键；probe 再次确认 `journal` 末条、fold、`loadMemory().text` 三者逐字节一致，而 `MEMORY.md` 可保留 `nowRaw`。测试断言应只比较 `memoryComparisonKey`/fold。

- §9 的"两类分开"方向正确且必要：自查抓住了 `lastWrite`/CONTEXT 的真回归，避免了 R4-IM-1 字面执行。
- 四时序回归探针全绿：no-edit 与今天逐 op/text 和 `MEMORY.md` 字节一致；窗口编辑 → `written:false external-edit-during-publish`、`nowKey` append、`MEMORY.md` 保留 `nowRaw`、重跑 `basisKey === key(E)` 且含 E 字节、最终 `E→D`；清空按 R-15 发布且无"未发布"日志；clear-then-write、same-as-rendered、CRLF 均符合 §6 定稿。

- R4 的 11 条 nit 中 10 条真解决，行号修正（`:151`/`:160`/`:138-142`/`:106`/`:92-93`）经源码逐一对照无误。
