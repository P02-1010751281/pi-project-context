## B. 薄弱假设实测（结论：假设为假，但 v7 的调用点结论仍成立；无 blocking）

用真实 `loadMemory`（`store.ts:87`）+ 真实 `recordMemoryDocument` + v7 顺序补丁实测：

| 构造 | `loadMemory().text` | 结论 |
|---|---|---|
| journal=[A]，`MEMORY.md` 更新为 B 且 mtime 更新（尚未采纳） | **B = render**（≠ fold A） | **"journal 存在就一定返回 fold"为假** |
| 同上但 mtime 回退（`utimes` 拨回） | **A = fold** | render 不被选中 |
| v7 调用点：pass 读 A → 调用期编辑 B → 调 `recordMemoryDocument(...,{basisKey:A})` | **② 先 append B**；③ `loadMemory()` = fold **B**；返回 `{written:false, kept:B}`、journal `[A,B]`、reply C 从不进 journal、errors.log 恰 "adopted…"+"not published…" | 假设的**结论**（§2.2 不需要再 append）成立，但成立原因是 **② 早于 ③ 且 ② 把 journal 变成最新**，不是"loadMemory 总返回 fold" |

对任务给出的反例链的实测否证：**"采纳块没触发（mtime 回退等）⇒ §2.2 也判陈旧 ⇒ 新字节只在 MEMORY.md"不成立**——mtime 回退时 `loadMemory` 返回 fold，§2.2 根本判不出陈旧，于是发布 C 并覆盖 B（`probe-keys-B.mjs` §5：journal `[A,C]`、render C）。这是已列入 §5 R-1 的既有语义，不是检出却不落 journal。

真正"检出却不落 journal"的窗口只有一处：**① 的入口读与 ② 的 `stat` 之间编辑落地**（`__afterEntryRead` 注入 E：② 用旧 `renderRaw` 判定 `external === foldedView` 不采纳，③ `loadMemory` 读到 render E 判陈旧并 return，journal 仍 `[A]`）。实测其后果**不是 R3-B1**：E 一直是生效内容，且下一次写路径的 ② 会先采纳 E 再基于 E 发布（`probe-timings.mjs` micro-window：call1 `written:false`、journal `[A]`、render E；call2 `basis2=E`、`written:true`、journal `[A,E,C]`）。**v7 没有重跑，所以 R3-B1 的"重跑用丢弃回复当基线"这一步不存在；不报 blocking。** 该窗口记入 residual-risk/learning。

### IM-B. §2.2 的 raw/raw 比较在"读取来源翻转"时假陈旧，并写出与事实相反的 errors.log
【修正已有机制】对应 **F3**（日志措辞）+ 与 R-8 同族的假陈旧

### IM-C. §4 的 repro exit 谓词按字面不成立，有把回归线重新做成假红/假绿的风险
【修正已有机制】对应 **F4**
- **file:line**：`design.md:184-185`（"`exit` 判定改为 `bEffective && adopted` 为 0"）；`repro-write-ordering.mjs:76-78`（现为 `reproduced = adopted && !bEffective`；`process.exit(reproduced ? 0 : 1)`，头注释声明 0 = 复现）。
- **影响**：修好后两条场景都是 `adopted=true && bEffective=true`。`bEffective && adopted` 本身是真值，"为 0"只能被读成计数或相反数；若实现者写成 `reproduced = fresh.bEffective && fresh.adopted && …` 再沿用 `exit(reproduced?0:1)`，脚本会在"已修复"时以退出码 0 退出——正是 R6-IM-3 想消灭的假通道（方向反了）。
- **修复边界**：把谓词与头注释一起钉死，例如：
  ```js
  const fixed = fresh.bEffective && fresh.adopted && stale.bEffective && stale.adopted;
  console.log(`判定：${fixed ? "编辑已守住（采纳且生效）" : "未守住——编辑被顶掉"}`);
  process.exit(fixed ? 0 : 1);   // 0 = 回归线通过
  ```
  并同步 `repro-write-ordering.mjs` 头部"退出码 0"的说明。

## learning

- **`loadMemory` 的渲染选择规则**：journal 存在时，只有"render 非空 + key ≠ fold + render mtime **严格大于** journal mtime"才返回 render，否则返回 fold。所以"journal 存在 ⇒ 返回 fold"是错的；但"② 刚 append 过 ⇒ 返回 fold"是对的。§2.2 的安全性来自 §2.0 的顺序，而不是这一假设。
- **`memoryComparisonKey("")` = `"# Project Memory\n"`，"空"与"空文档"不是一个 key**——任何比较都要两侧同做 `trim() ? key : ""`（R6 的 blocking 成因，v7 已守住）。
- **`memoryComparisonKey` 的归一化边界**：只删文档级首尾空白/尾换行与序言头；内部 `\r`、内部行尾空格原样保留（probe 实测）。CRLF/行尾空格的编辑会被视为不同 ⇒ §2.3 触发并 append 规范化键，安全侧。
- **无重跑世界里的"检出却不落 journal"是自愈态**：①/② 竞态下编辑留在 `MEMORY.md`、保持生效，下一次写路径的 ② 先采纳再发布；R3-B1 的伤害依赖"重跑拿被丢弃回复当基线"，该依赖已随重跑取消而消失。
- **§2.4 的"按主体而非按行块"归类是对的**，避免了 R5 class-1 把 `!memoryChanged` toast 与 `contextShapeWarned` 一起门掉的回归；v7 对 `contextShapeWarned` 选"留"也与无重跑一致（v5 的"拒绝态不消费"是重跑世界为了不烧掉中间 attempt 的一次性告警；v7 里被拒绝的回复就是唯一 attempt，警告描述的是仍然成立的 CONTEXT 状态）。

## residual-risk

- **①/② 读取竞态**（新增描述）：编辑落在入口读与采纳 stat 之间时，② 不采纳但 §2.2 检出；字节只在 `MEMORY.md`、保持生效，下一次写路径采纳（probe 实证）。若要消灭"检出却不落 journal"的最后一格，需在 §2.2 也做 §2.3 式 append——属**新增机制**、无 F1–F4 现场事实，建议只记录。
- **同毫秒/粗粒度 mtime 相等**（既有，probe `probe-adversarial.mjs` §3）：render 与 journal 的 `mtime` 相同会让采纳与读取选择都看不见编辑（R-1 家族）。建议在 R-1 措辞里把"回退"扩为"回退或同刻"。
- **`activeConsolidation` 模块级、不按 projectRoot**（既有，v5 R-19）：跨项目 join 会让 B 拿到 A 的 outcome；v7 的 basisKey 判据在内容不同时拒发（今天是无条件写），缩小了爆炸半径，但内容恰好相同的两个项目（如两个全新项目 `basisKey=""`）仍会串写。§5 未列，建议补一条（非本设计要修）。
- **overflow 副本后置后的崩溃窗**：`writeAtomic` 成功 → `saveOverflowReply` 之前进程被杀 ⇒ 发布成功但副本缺失（D2 原文的"孤儿副本"方向反转）。best-effort 语义下可接受，建议在 §5/§6 点一句。
- R-1…R-10 全部维持（mtime 回退覆盖、recheck→rename、清空胜出、拒绝分支跳过 rotation/gitignore、cap 变更假陈旧、rotation 32000 折叠、⑥ 中途被杀）——与 v5 边界一致，无夸大。
