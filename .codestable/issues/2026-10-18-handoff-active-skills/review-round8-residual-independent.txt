# R8 Independent Review: residual cleanup (standalone `.md`, nested file ops)

## Verifications against installed pi (1.3.0)

- **`parseSkillBlock`** (`dist/core/agent-session.js:53`): anchored regex `<skill name="([^"]+)" location="([^"]+)">…`; name always non-empty. The block is produced by `_expandSkillCommand` (line 1710) as `<skill name="${skill.name}" location="${skill.filePath}">`, so a real `/skill:` block's location is the skill's own file path — for a standalone skill that is the `.md` path, and the name is the loader's name.
- **Skills loader** (`dist/core/skills.js`): `loadSkills` accepts a file path only if it `endsWith(".md")`; `loadSkillFromFile` requires a non-empty `description` for any non-`SKILL.md` file, so a *non-skill* `.md` never enters the skill map and can never produce a `/skill:` block. → Accepting any `.md` location in a `/skill:` block is **correct**: the block is the explicit evidence, and genuine blocks only exist for loader-verified skills. The `.md`-extname guard matches pi's own acceptance domain (pi's `endsWith(".md")` is case-sensitive; the extension's `toLowerCase()` is slightly more lenient, harmless).
- **`extractFileOpsFromMessage`** (`dist/core/compaction/utils.js:16`): toolResult → `nestedCalls?.calls`, `addFileOp(name, arguments)`, status never read; assistant → toolCall blocks, `name`/`arguments` required. The extension mirrors this exactly (read/write/edit, `arguments.path`, no status check), with defensive guards pi lacks (pi throws on a `null` call; the extension skips — the test `malformed nested calls do not throw` pins a shape pi itself would crash on, which is the right call for a handoff path). `computeFileLists` is byte-equivalent to pi's (modified precedence, sort). Only divergence: pi's `if (!path) return` drops an empty-string path; the extension's `typeof file !== "string"` check admits `""`. No real tool emits `""`; no test.
- **`skillName` fallback**: `meta.name || skillName(file)` — `meta.name` is always present for `/skill:` (regex `+`), so the fallback never applies to standalone files (which can only arrive via `/skill:`); read/compaction/prompt sources still fall back to parent dir. Dedupe/priority/cap unchanged and hold: a direct read of a standalone `.md` is filtered by `isSkillFile`, so no competing lower-priority entry can exist for it; the both-orders dedupe test covers the directory form. The block name now wins over the parent-dir guess, which is also what pi itself names the skill (`frontmatterName || parentDirName`).
