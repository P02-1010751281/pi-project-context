## Findings

- **nit** — `extensions/project-context/handoff/file-ops.ts:112`, `fix-note.md:30,93`: "MCP" is named as a nested-call producer, but only tools that receive `ctx.executeTool()` can produce `nestedCalls` — that is extension tools (codemode is one). The MCP tool wrapper's execute is `(_toolCallId, params, signal, onUpdate)` (`pi-coding-agent/dist/extensions/mcp/tools.js:255`) and never touches the context; remote MCP servers cannot call the host's recorder. MCP tools are nested-call *targets* (`getCallableTools`), not producers. Impact: record accuracy only (the class R6 dinged), no behavior; docs/CHANGELOG wording ("工具结果上记录的嵌套 `read`") is neutral and fine. Fix boundary: say "extension tools (e.g. codemode scripts)" in the comment and the two fix-note parentheticals.
- **nit** — `fix-note.md:56-62`: the verification paragraph names only the positive nested read; the three new negative pins (nested write ignored, non-SKILL nested read ignored, malformed no-throw) are enumerated nowhere except indirectly via the mutation row's errored pin. The fix-note's convention enumerates pin coverage; one sentence would complete it.
- **suggestion** — `tests/handoff-test.mjs:164-204`: no pin for a non-array `nestedCalls.calls` or `nestedCalls: null` (both skip via the `Array.isArray` / `nestedCalls &&` guards; no-throw holds but is unpinned). Low value — the malformed pin covers the guard family.
- **learning** — pi's own `extractFileOpsFromMessage` for-ofs `nestedCalls?.calls ?? []` without an `Array.isArray` check, so a corrupt session file with non-iterable `calls` would throw inside pi's compaction; the repo mirror is more defensive while matching semantics. Also, `NESTED_CALL_LIMITS` (8 KB/call, 32 KB total) omits `arguments` entirely for oversized nested calls — such reads are invisible to both pi and this scan (undisclosed corner; residual-risk).
- **praise** — every R6 claim reproduced: the 2-FAIL mutation, the start-recorded/status-ignored semantics, the `nestedCalls` shape and persistence path, the standalone-`.md` invisibility (all five sources), and the `collectFileOps` asymmetry. The docs' "其次真实 `read`" tier wording remains accurate: a nested read is a real read execution, sharing tier 3.
