## important

**I-1 `threshold.ts:216` — 过度修正守卫只认 `scaled <= 0`，符号为正但仍被 rate 过度修正的样本会继续把 `min` 拉到物理下限之下（与 R1#1 同类，修复未闭合）**

- 现场事实可推：`probe-true-baseline.md` 实测物理下限 **≥ 11,021**（隔离 ctl，无注入块）/ **17,766**（本仓含注入块）。baseline 读成三位数物理上不可能，与 R1#1「baseline 不可能是 0」同一条现场依据。
- 独立复现（自造夹具，ASCII 前缀 + CJK 尾；夹具用法与作者 1c 同构，只把 ASCII 首块从 60,000 改成 ~20k–25k）：
  - `ascii=60_000`（作者的夹具）：`scaled = 32766 - 57143 < 0` → 守卫生效 → `baseline=17766` ✅
  - `ascii=20_000`：`scaled = 22766 - 19030 = 3736 > 0` → **守卫不触发** → `baseline=3736`
  - `ascii=25_200`：`baseline=106`；`ascii=24_000`：`baseline=947`
  - 同一支分支**去掉 CJK 尾**时该模块报 `17,766`；**加上 CJK 尾**反而塌到 `106`。分支增长只能让真值基线不变，读数却掉 17.6k——正是本 issue 要修的「baseline 随分支漂移」的反向复现。
- 根因：`atRate(plain)=chars/rate` 只对**与校准窗口同率**的前缀有效。当前缀比校准段更稀（ASCII，r≈4）而尾段更密（CJK，rate≈1.05）时，`scaled = prompt - chars/rate` 可以落在 `(0, baseline_true)` 区间，既不触发守卫、又低读。CHANGELOG:26 的「会高读、不会低读」与 design.md:39/112 的「只高不低」只对 `scaled ≤ 0` 成立，对 `0 < scaled < 真值` 不成立。
- 最小修法（二选一，须先落一条会红的契约）：
  1. 新增契约：`ascii≈25_200 + CJK 尾` 的夹具必须 `baseline >= 11_021`（或 `>= prompt - plain`）；现实现会红。
  2. 代码侧：不允许一个「其前缀未被任何 rate 校准 delta 覆盖」的样本独自推动 `min`（例如要求样本所在段与校准段同率，或退到 design §5.1 已写过的「最早一条」语义），至少让守卫覆盖 `0 < scaled < chars/4 残差` 的整段，而不是只看符号。若判定这是可接受的取舍，也必须把这条写进残余登记并把「只高不低」改成有范围的措辞——当前两处都没有。

## suggestion

- **S-1 补边界契约**：作者契约只覆盖 `scaled<0`。加一条 `scaled===0` 的样本（或直接断言 `residual` 在 `scaled<=0` 时取 chars/4）——我的变异 `scaled > 0` → `scaled >= 0`（M1）全绿，说明恰好归零的边界无覆盖。
- **S-2 钉住 rate 的窗口**：`RATE_PAIRS` 5→1 全绿（M4），中位数窗口大小无契约。若 5 是有意设计，加一条「>5 个 delta 时取最近 5 个中位」的纯函数契约。
- **S-3 钉住 `atRate` 的取整方向**：`Math.ceil`→`Math.floor` 全绿（M6），±1 被 ±2 容差吃掉。
- **S-4 `run.ts` 每次 status 行重复走分支**：`run.ts:57` 调一次 `measureContext`，`resolveThreshold`/`thresholdRefusal`/`thresholdRefusalText` 各自再经 `baselineTokens` 调一次，长会话下是 4–5 次全量 walk。非本轮回归（旧 `baselineTokens` 也多次调用），登记即可。

## learning

- 单向守卫修不了双向误差：把「过度修正」等同于「残差被夹到 0 / 转负」，漏掉了「过度修正但残差仍为正」的整段连续区间（本例 0–~25,295 字符）。修一个符号缺陷时，应先把出错量的**值域**画出来再决定守卫形状，而不是只处理报错的那个点。
- 「模块输出当期望值」的契约在误差同向缩放时恒真（N-3）；纯函数契约里凡是拿被测模块的一个输出进期望，都应配一条绝对常数钉。
