## 本轮改了什么（**这是待验证的主张，不是结论**）

`baselineTokens`（物理下限 `floor = baseline + keep + MIN_DROP_TOKENS` 里那个 baseline）原先取「当前这一点的 usage 残差」，
而残差 = 真值 + `Σchars × (1/4 − 1/r)`（本仓探针实测 `r = 2.2–3.8`），于是 floor 随会话变长自己长高，越过质量拐点后自动交接
被**无声**关掉（现场：prompt 317k、floor 179k > knee 157k）。本次改动：

1. `measureContext(ctx, usage)`：走完分支上每条 assistant 记录，取 `prompt = input + cacheRead + cacheWrite`（**不含**该记录的 `output`）
   与**该记录之前**的消息估计（记录自己的消息不算进自己的 prompt），取**最小残差**作为 baseline；
   rate = 最后 5 个「同段」delta 的中位数（`4·Δ估计/Δprompt`），取值带 `[1.0, 8.0]`，无可用 delta 时 rate = 4 且 `calibrated=false`；
   **无 usage 记录时逐字节走旧公式**。
2. `contextTokensAtRate()`：回执 `dropping ~X / carrying ~Y`、mid-turn 快照预算、`keptTokens`、`anchorTokens` 四处改用它
   （共 4 个调用点）。**切点本身仍是 pi 的 `findCutPoint`（chars/4）**，本轮不动。
3. `baselineSuffix()`：`/handoff status` 加 `· baseline <值> (<rate> c/t, best of <n>)`；无样本时写 `(chars/4, no usage sample)`。
4. 另修一条与本改动无关的测试竞态：`consolidation-test.mjs` 读 `CONTEXT.md` 不等写入（作者称已在父提交上复现）。
