## Important

- `docs/architecture.md:134-139` — **Overpromises the refusal guarantee.** The sentence says a mid-pass change to stored `MEMORY.md` means the whole reply, including its `context` section, is never published. That is false when the reply’s memory is semantic-empty or too short: `memoryChanged` is false, the `recordMemoryDocument`/`basisKey` path never runs, `memoryRefused` stays false, and a valid reply `context` is still written. I reproduced this in a scratch probe: `MEMORY.md` was changed during the model call, the reply carried a bare memory skeleton plus a valid context, and `CONTEXT.md` was overwritten with the reply’s stale summary while the notice said “context updated; memory was kept unchanged”. This is the R1 residual already recorded in `fix-note.md:73-76`, but the architecture page states the stronger guarantee without qualification. Smallest fix boundary: qualify the sentence to replies with a publishable memory change (or add the R1 caveat explicitly). No new production mechanism needed.
