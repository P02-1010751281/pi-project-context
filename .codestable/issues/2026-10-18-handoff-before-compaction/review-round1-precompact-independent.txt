## Learning

- **Ordering verified in pi 1.3.0** (`dist/core/agent-session.js:~1420-1441`): `_handlePostAgentRun()` → `_checkCompaction()` → `_runAutoCompaction()` (emits `session_before_compact`) → `_runBeforeSettleBoundary()` → `agent.continue()`/break; `_emitAgentSettled()` runs in the `finally` — so `session_before_compact` always precedes `agent_settled` and the settle event fires even after a cancel. The record's line-for-line claim is accurate.
- **Cancel semantics verified:** `{ cancel: true }` → `cancelledByExtension` → throw → `compaction_end`/`session_compact_failed` with `aborted: true, willRetry: false`, `_runAutoCompaction` returns false, `_failedResponse` never set → no retry, no stale retry, and `_overflowRecoveryAttempted` resets on the next user message or successful assistant message. Cancelling `overflow` (willRetry) is safe and leaves the session usable.
- **"Intact branch" holds even for overflow:** `_omitRecoveryAttempt` runs *before* the hook, but it only appends a `context_edit`; `buildContextEntries` ignores edits and `sessionEntryToContextMessages` skips them, so the handoff's own replay still sees the failed turn in the raw branch.
- **Manual exemption is reachable:** `AgentSession.compact()` emits `session_before_compact` with `reason: "manual"` (agent-session.js:~2204-2230).
- **Fail-safe bias:** a stuck `handoffInFlight` disables the guard (compaction proceeds) — the failure mode leans toward pi's own compaction, never toward cancel-forever.
- **Multi-extension:** the runner returns the first `{cancel:true}` and short-circuits, so the guard's cancel dominates other handlers' compaction content.

## Praise

- `session_before_compact` is the right hook — it is pi's only cancellable point before compaction (`agent_before_settle` runs after; supplying a `compaction` result would still compact).
- `handoffDue` matches the settle trigger's conditions exactly (enabled, in-flight, TUI, usage null, refusal, at/above threshold); `maybeTrigger`'s refactor is behavior-preserving.
- Threshold geometry is coherent: the adaptive line sits 4K below pi's compact line, so whenever pi auto-compacts and a handoff *can* trigger, the guard sees it due; when `resolveThreshold` refuses, the settle trigger would never fire either, so letting pi compact is correct. Fixed ratios above the reserve line get the same single-turn-crossing protection.
- Mutation matrix reproduced exactly as claimed: remove handler → 2 FAIL, exclude overflow → 1 FAIL, remove TUI guard → 1 FAIL, remove cooldown/backoff guard → 1 FAIL.
- Skip/failure/busy paths all arm a clock, so no cancel-forever path exists in the code as written; only I-1's pin is missing.

## Residual risks

- `_prepareRun` cancellations let a prompt run above threshold before the settle-time handoff (documented).
- After a cancelled overflow compaction, `_overflowRecoveryAttempted` stays true until the next user message / successful reply; if the handoff then fails and the user immediately overflows again in the same session, pi would skip compact-and-retry once — mitigated by the failure backoff letting the next threshold compaction through and by the flag reset.
- Module-level cooldown/backoff persist into the successor session (pre-existing design).
- pi's cancel-merge semantics (first cancel wins) is a runtime behavior of 1.3.0; a future pi change to result merging would need re-verification.
