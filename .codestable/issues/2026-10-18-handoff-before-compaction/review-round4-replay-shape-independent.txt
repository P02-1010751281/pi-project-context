## BLOCKING

**1. The strip shape still crashes real pi — the replay persists assistant messages without `usage`, and pi's own consumers read `.usage` unguarded.**
`extensions/project-context/handoff/text.ts:125-130` deletes `usage` from replayed assistants. That fixes the R3 classifier crash, but the successor session now contains persisted assistant entries with `usage === undefined`, which violates pi 1.3.0's invariant (`AssistantMessage` declares `usage: Usage` required, pi-ai `types.d.ts:375`). Two crash paths, both reproduced end-to-end against the real pi 1.3.0 modules:

- **TUI footer, every frame, immediately** — `modes/interactive/components/footer.js:104-107` (pi 1.3.0): `addUsageToTotals(usageTotals, entry.message.usage)` then `entry.message.usage.input + …` over all entries ("footer renders on every frame", footer.js:77). Probe with the real `SessionManager` + `appendMessage` + real `usage-totals.js` → `TypeError: Cannot read properties of undefined (reading 'input')` on the successor's first render. No compaction needed.
- **`getContextUsage` after the successor's first compaction** — `core/agent-session.js:3486-3488`: after any compaction whose keep window retains a replay entry (`buildContextEntries` keeps entries from `firstKeptEntryId` on; defaults make this the common case — `handoffBudgetRecentTokens` 20k ≈ pi `keepRecentTokens` 20000), the projected stripped assistant passes `stopReason !== "aborted"/"error"` and hits `calculateContextTokens(message.usage)` → `TypeError: …(reading 'totalTokens')`, confirmed by probe with real `buildSessionProjection` + `calculateContextTokens`. Trigger: manual `/compact`, threshold compaction on small-window models (there `U <= F` refuses the handoff threshold, so the guard never cancels), or overflow-with-retry (explicitly left to pi). Every subsequent call crashes: the TUI footer (footer.js:118) **and the extension itself** — `handoffDue(ctx, ctx.getContextUsage())` at `run.ts:347` (`agent_settled`, line 400) and `run.ts:419` (`session_before_compact`) → handoff trigger and guard permanently dead, extension error every settle. Same latent shape in `getUsageStats` (agent-session.js:3444-3446) and cache-warmer `lastPromptTokens` (cache-warmer.js:48-53).

This is inherited from 0580b2d (R3 caught only the `isContextOverflow` crash, which this patch does fix); dropping `stopReason` does not touch these paths — they read `usage` itself. **Smallest fix boundary**: in `withoutReplayUsage`, replace the `usage` field with a zeroed usage record (`{ input: 0, cacheRead: 0, cacheWrite: 0, output: 0, totalTokens: 0, cost: {…0} }`) instead of deleting it, while still dropping `stopReason`/`rawStopReason`. That keeps the classifier fix (stopReason absent → `isContextOverflow` never reads usage), keeps `_checkCompaction` on the estimate path (directContextTokens 0), makes footer/getUsageStats/cache-warmer add zeros, and turns the post-compaction `getContextUsage` case into the graceful "tokens unknown" state. Update the A-2 checks to pin the zeroed record and add a regression test that runs the installed pi's real `addUsageToTotals` and `calculateContextTokens` over the replay (import from the pi dist exactly like the existing `isContextOverflow` import at `tests/handoff-test.mjs:344`).
