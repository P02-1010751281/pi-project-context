## Findings

**Praise**
- `text.ts:117-143` — the zeroed record mirrors pi's persisted usage shape exactly, is fresh per message (probe-verified), and never mutates source entries.
- `tests/handoff-test.mjs:347-357` — pins the real installed pi consumers; four independent mutations go red exactly as claimed, including reproducing R4's actual TypeError.
- `run.ts:361-368` + `docs/handoff.md:19` — the async-send boundary is documented precisely against pi's real API behavior, not guessed.

**Nit**
1. `tests/handoff-test.mjs:341-357` — freshness of the zeroed record is unpinned: a shared-mutable-record mutation passes green. Smallest fix: two-assistant fixture asserting `a.usage !== b.usage && a.usage.cost !== b.usage.cost` plus mutation isolation.
2. `tests/handoff-test.mjs:340` — the A-2 fixture usage lacks `cost`, unlike real persisted records (so the stale-usage mutation's crash is partly a fixture artifact; the zeroed assertions still pin stale usage independently).
3. `docs/handoff.md:126` — lists only the English marker literal while claiming zh/en; listing both keeps the doc self-contained.

**Residual-risk (all acceptable, documented)**
- `text.ts:135-143` → `virtual-models.js:12-19`: replayed assistant counts as "latest successful response" (missing stopReason). Pre-first-call `routedModel`/router `previous` name the predecessor's model; wrong only for an aborted predecessor tail. No crash, no compaction impact.
- `cache-warmer.js:47-53,284`: `lastPromptTokens` returns 0 on a replay tail → warming pauses one turn in the successor. Heuristic-only, benign.
- `run.ts:361-368`: async send rejection → `handoffInFlight` stuck true → auto handoff silently dead for the session. Unobservable via the extension API; docs scope it. Watch if pi ever exposes the rejection.
- Positive side effect worth noting: zeroing also removes a latent R4-era edge — stale usage would have made the successor's `getContextUsage` report a huge percent and immediately re-trigger handoff.

**Learning**
- Zeroing rides on pi's own "invalid usage" filters (`getAssistantUsage` `> 0` guard; `projectedAssistants` `> 0` guard), which is why zeroed records are simultaneously shape-valid, crash-free, and invisible to stale-usage accounting. The `calculateContextTokens === 0` pin is what indirectly guards the arrival-compaction property.
