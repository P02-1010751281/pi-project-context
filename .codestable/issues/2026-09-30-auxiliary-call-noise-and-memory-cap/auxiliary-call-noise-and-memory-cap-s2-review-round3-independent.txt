## New findings

1. **nit (test hole) — `clipProse`'s normalization is unpinned.** `extensions/project-context/memory/context-doc.ts:34`. Replacing `const normalized = normalizeLine(value)` with the raw value **survives 13/13 and all 33 S2 checks**; a summary `"a\n\n\n\nb"` then renders as four lines instead of `a b`. Every test summary is whitespace-free. Impact: a real normalization regression is invisible. Minimal fix boundary: add one summary containing newlines/tabs asserting the collapsed single-line body and exact `dropped`.

2. **nit (test hole) — the `full` baseline's normalization is unpinned.** `context-doc.ts:49-50`. `content = items.filter((item) => normalizeLine(item).length > 0)` (keeping raw items) survives 13/13; probe shows `key_points:["  a  b  "]` then emits a **false** `_[context truncated: 5 characters dropped]_` although nothing was clipped — exactly the misreport class round 1 targeted. Minimal fix boundary: assert a whitespace-padded item renders normalized with no marker, or assert exact `dropped` excludes normalization.

3. **nit (test hole) — the once-per-project gate is masked by `logError`'s own dedupe.** `report.ts:27,132` vs `shared/error-log.ts:23,91`. Removing `!contextCapWarned.has(projectRoot)` survives 13/13: identical `(scope, headline)` records inside the 10-minute window are swallowed, so `"a second truncated pass does not log again"` (`context-schema-test.mjs:141`) is satisfied even without the Set. Impact: the Set could regress to a no-op unnoticed. Minimal fix boundary: make the second pass materially different (new headline/version) or clear the error-log dedupe state between passes.

4. **nit — `isContextTruncated` accepts a singular "character".** `context-schema.ts:48` uses `characters?`, while the generator (`:52`) and docs emit `characters`. `isContextTruncated("_[context truncated: 5 character dropped]_")` is true, so the "strict shape" isn't exactly one shape. Impact is negligible (only affects diagnostics detection) and the test's near-miss still catches non-digit forms. Minimal fix boundary: plural-only regex, or state the tolerance in the comment.

5. **learning — whitespace normalization is silent and uncounted by design.** `context-doc.ts:19-20`. Backslashes survive unchanged; NBSP/U+3000/CR/LF collapse to a single space and empty items disappear, none of which enters `dropped`. The marker never misreports a cap loss, but `docs/configuration.md:68`'s "以未 trim 的完整渲染为基准" could be read as the raw input rather than the *normalized* untrimmed render. Not a defect; wording could say "normalized but untrimmed".

6. **nit (quality) — two minor boundary smells.** `context-doc.ts:58-59` initializes a Record with zeros and fills it in a loop, only for `contextSectionBudgets()` to be called a second time at `:74`; and `clipProse`'s `Math.max(0, limit)` at `:36` is unreachable because budgets are already clamped non-negative (`context-schema.ts:82`). Impact: readability/duplication only; hoisting `const budgets = contextSectionBudgets()` and dropping the clamp would be equivalent.

## Praise

- The one-table guarantee is real: `context-schema.ts:27-31` feeds prompt (`prompt.ts:19-21`) and renderer (`context-doc.ts:59,74`); shares sum to 1; floor + `min(share, maxChars)` is correct.
- The marker arithmetic is now genuinely exact, not shape-only: 800 randomized differential cases agree byte-for-byte, and all 23 mandated mutants plus 4 extras die in the S2 test alone.
- The cap guarantee is still real with wide margin: `overhead(349) + Σbudgets(24989) = 25338 ≤ 32000`; the extreme render is 24 013, a 60 MB-class input is 10 669, and even an 8-digit dropped count cannot consume the ~6.6k headroom. The 5-digit reserve is conservative, never load-bearing at the fixed cap.
- Backward compatibility is untouched: `parse.ts` fail-closed path and the archive read-only injection have zero diff; free-form CONTEXT.md loading is unchanged.

## Residual risk

- **F8 read-side silent slice remains** (`archive/archive.ts`, `pass.ts:74`): an externally written free-form CONTEXT.md > 32 000 chars is still sliced mid-line on injection with no marker. Explicitly out of scope in the design note and not pretended otherwise; the "no silent truncation" guarantee applies only to extension-written files.
- **The marker reserve is cap-parameter-independent** (`context-schema.ts:71` always sizes for `MAX_CONTEXT_CHARS`); harmless now, but if a configurable context cap (out of scope) ever lands, the reserve must follow the passed `cap`.
