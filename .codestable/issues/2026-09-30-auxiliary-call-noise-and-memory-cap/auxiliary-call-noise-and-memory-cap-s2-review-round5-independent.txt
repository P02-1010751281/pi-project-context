## 3. New adversarial observations

1. **nit — whitespace tolerance of the tail scanner is unpinned.**
   `context-schema.ts:61` (`.map((line) => line.trim())`) — the trim-only mutant `text.split("\n").filter(len>0)` **survives all 38 S2 checks** (`/tmp/r5/work3`). Behavior itself is correct: probes show `marker\n\n\n`, `"  marker  "`, and `x\r\nmarker\r\n` all return `5`; the blank-line `.filter` *is* indirectly pinned by the written-file check. Impact: a regression that stops tolerating CRLF/padding would go unnoticed; production only parses the freshly rendered LF document, so no functional impact today. Minimal fix boundary: one check feeding a padded/CRLF/trailing-blank marker to `contextTruncationDropped`.

2. **learning — tail-scoping makes the helper a fresh-render detector, not a stored-file detector.**
   Probe: `head\n<marker>\ntail\n` → `undefined`; a synthetic marker-only summary with no trailing comment → detected. Only consumer is `report.ts:132` on the in-memory render just written, which always ends with the `<!-- latest-session-title -->` comment, so this is correct-by-contract (doc comment at `:56-58` says so). Note the asymmetry with `isMemoryTruncated` (`document.ts:30`), which scans any line; a future read-side consumer would need a different policy. No fix required.

3. **suggestion — prompt marker example names only the memory shape.**
   `prompt.ts:41` says “any line like `_[memory truncated …]_`”, while S2 now injects a `_[context truncated: N characters dropped]_` line in `<existing-context>`. The renderer's normalization + tail-scope neutralizes a copied context marker (no false clip; verified by the phantom test), but a copied line can still occupy section budget/body text. Minimal fix boundary: add the context shape to the example.

4. **learning — `contextSchemaOverheadChars` over-reserves the marker by one char.**
   `context-doc.ts:81` appends net `marker + 2` (replaces the final `\n` with `\n\n<marker>\n`), while `context-schema.ts:82` reserves `marker.length + 3`; conservative and safe, and pinned by `overhead === 349`. No action.

Quality bars: the one-table design (`context-schema.ts:27-31` → `prompt.ts:19-21`, `context-doc.ts:58-75`) has clear renderer/prompt/report boundaries, no dead `slice` fallback, no over-guarding beyond the reachable small-cap clamps, and readable comments that match the code. Only repetition is the `entry` union spelled at `context-schema.ts:13,33` and the two `Record<…["entry"]>` maps at `context-doc.ts:59,65` — cosmetic. `MAX_LIST_ENTRIES` is imported from `project-state` in one file and `limits` in another, existing style. Out-of-scope boundaries are clear: `parse.ts`/`archive/`/`pass.ts` have a 0-line diff, and nothing pretends to implement S4, a configurable context cap, or read-side migration (the pre-existing read-side `.slice(0, MAX_CONTEXT_CHARS)` at `archive.ts:117`/`pass.ts:74` is unchanged and correct for S2's ~25k outputs).
