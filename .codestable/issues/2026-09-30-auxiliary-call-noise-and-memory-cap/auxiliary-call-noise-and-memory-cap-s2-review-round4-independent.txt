## New findings

1. **nit (test hole / fragile pin) — the logged dropped count is never asserted, so NEW-3's pin can be silently re-masked.**
   `extensions/project-context/memory/context-schema.ts:61-67`, `report.ts:132,136`, `tests/context-schema-test.mjs:177,184`.
   Evidence: mutants `contextTruncationDropped` returns `0` (M26), `Number(match[0])` = `NaN` (M27), and message without `${dropped}` (M29) each **survive all 13 tests**; combined with gate-off they also survive (the second message becomes byte-identical and `logError`'s `scope\0headline` dedupe, `shared/error-log.ts:23,35,91`, swallows it). So the gate kill only works while the count happens to be present and change.
   Impact: `errors.log` can report `0`/`NaN` or omit the count unnoticed, and the once-per-project Set can regress to a no-op again without any test failing.
   Minimal fix boundary: in the second-pass block, assert `logged[0]` contains the exact number the written marker carries (e.g. `contextTruncationDropped(written)` compared against the marker) and that the two logged numbers differ; no production change needed.

2. **nit — `contextTruncationDropped` picks the *first* marker-shaped line, not the appended one.**
   `context-schema.ts:61-66` vs `isContextTruncated:56-58`; consumed at `report.ts:132-136`.
   Evidence (probe): `{summary:"_[context truncated: 5 characters dropped]_", key_points:["y".repeat(5000)]}` renders a file whose real marker is `4200`, but `contextTruncationDropped` returns `5`; with no real clip (`summary` only) it returns `5` and `report.ts` would log “CONTEXT.md was clipped … 5 characters were dropped” although nothing was clipped (summary is a section body, so a whole line can match the anchored regex). Prior `isContextTruncated` had the same false-positive class, but the new function turns it into a fabricated number.
   Impact: wrong/phantom clip diagnostics once per project per process (the stored file is unaffected); trigger is a model summary exactly equal to the marker line — the prompt forbids markers, but the previous render is injected and models drift.
   Minimal fix boundary: make detection tail-scoped (marker must be the last non-empty line) or scan lines in reverse; one shared helper for both predicates.

3. **nit (design-note drift) — the design still credits `isContextTruncated` to report and keeps the old `dropped` wording.**
   `design:18` (“导出 `isContextTruncated` 供 report 告警”) vs `report.ts:12,132` which imports `contextTruncationDropped`; `isContextTruncated` is now test-only in production. `design:32` still says “未 trim 的完整渲染” while `:18` and configuration.md:68 say “归一化但未 trim”. Impact: reviewers/implementers reading the note get the wrong function and an incomplete baseline. Minimal fix boundary: two sentences in the design note.

4. **suggestion (duplication) — two independent line scanners for one marker.**
   `context-schema.ts:56-58` and `:61-66` parse/scan separately; this is exactly how finding 2's first-vs-any-line drift arose. Minimal fix boundary: implement `isContextTruncated(text) = contextTruncationDropped(text) !== undefined` (or a private `findMarkerLine`) once.

5. **residual-risk — the 160-char title trim is still a silent field loss.**
   `context-doc.ts:57` + `context-schema.ts:41-42`: a >160-char `title` is cut and never enters `dropped`/the marker (the test only checks surrogate safety, `:105-108`). This is deliberate metadata capping and predates S2 (not a section budget), but it is the one remaining `trimLine` loss with no trace; worth one sentence in the design's residual list.

Quality bars: no over-engineering/fragmentation beyond the duplicated scanner; the one-table design (`context-schema.ts:27-31` → `prompt.ts:19-21`, `context-doc.ts:58-75`) is clean and the comments match the code; boundaries between renderer, prompt, report and archive are clear; the `ContextSectionBudget` file is readable and mutation-tight (23/23 mandated mutants killed). The `entry` union is spelled out in three places (`context-schema.ts:13-24,33`, `context-doc.ts:59,65`) — a tiny DRY nit, not worth changing alone.
