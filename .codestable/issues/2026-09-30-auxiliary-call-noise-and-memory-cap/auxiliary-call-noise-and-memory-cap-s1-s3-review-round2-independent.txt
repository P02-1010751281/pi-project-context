## Findings

**R1 (important) — the description regression check is still self-referential; "remove the descriptions" survives the suite.**
`tests/memory-budget-test.mjs:71`, `schema.ts:19-22`, `prompt.ts:16`.
The expected string is built from `section.description` loaded from the same module being tested, so it only proves the prompt agrees with the mutated table. Mutation evidence (mutant copies in `/tmp`): removing the four `description` properties (prompt then renders `- ## Project: undefined (about 786 characters)`) and blanking/replacing the values both leave the suite **ALL OK**. Removing `${section.description}` from the prompt itself is caught (test:71), so only prompt↔module coupling is tested, not the documented content. Impact: the F3 fix (including "user preferences" having a home) can be silently reverted while the check named "the prompt lists every section with its description" stays green. Minimal fix boundary: add the four description strings to the hard-coded `documented` contract (test:48) and assert the prompt contains those literals (or at minimum assert `description.length > 0` and key terms); do not implement here.

**R2 (nit) — design doc still states the superseded formula and a weaker pointer rule than the code it records as implemented.**
`auxiliary-call-noise-and-memory-cap-s1-s3-design.md:50` (`每节预算 = maxMemoryChars × share`) contradicts `schema.ts:38` (overhead deducted first); `:56` still uses the repo-specific `157K/450K … docs/handoff.md` example and `:58` says only "已存在…对话或现有记忆里出现过", weaker than prompt.ts:27 ("already exists in this project and actually holds the detail"). The decision record `:79` says these were changed. Impact: a future S4 reader can implement the wrong formula/rule from the review-bound artifact. Minimal fix boundary: update/mark superseded 决策 3 and §S3 bullets; docs only.

**R3 (nit, residual of F1) — overhead reserves the header and heading prefixes but not the newlines separating section bodies, so the "逐节刚好填满也不会超 cap" guarantee is not literally true at some caps.**
`schema.ts:32-34`, `docs/configuration.md:66`, `tests/memory-budget-test.mjs:66-69`.
Probe (pristine copy, cap 4003): budgets `[787,1574,983,590]`, `overhead+Σ = 4002` (slack 1). A conventional document with each section body exactly its budget *including its final `\n`* and one blank line between sections measures `memoryDocumentChars = 4004 > 4003`, `exceedsMemoryCap = true`, and `normalizeMemoryDocument` emits a truncation marker. 68,600 of the 196,001 caps in [4000,200000] can exceed by 1–2 under that convention. The test's named "a document filling the real overhead and every budget stays within the cap" only adds numbers; it never constructs a blank-line-separated document. Impact bounded (1–2 chars, budgets are "about N"), but the docs claim a guarantee and a real exact-fill can still trigger the condensation call / middle clip. Minimal fix boundary: reserve one newline per section boundary in `memorySchemaOverheadChars` (and/or make the test construct the document at a slack-zero cap such as 4003), or soften the docs claim.

**R4 (suggestion) — the document header/heading format is duplicated across module boundaries.**
`schema.ts:33` hard-codes `"# Project Memory\n\n"` and `## H\n\n`, while `document.ts:16` owns the private `MEMORY_HEADER`; `tests/memory-budget-test.mjs:64` repeats it again. If the header changes, the budget overhead goes silently wrong. Minimal fix boundary: export/reuse the canonical header constant; not required for this change.

**R5 (nit) — unused flexibility in `memorySchemaOverheadChars(sections = MEMORY_SECTIONS)`.**
`schema.ts:32` — no caller passes `sections` (test:49 calls it bare and recomputes its own anchor at test:64), and `memorySectionBudgets` (schema.ts:37-39) maps `MEMORY_SECTIONS` while calling the parameterless overhead, so any caller using the parameter would desynchronize budgets. Minimal fix boundary: drop the parameter until S4 has a caller, or thread the same `sections` through `memorySectionBudgets`.

**Praise** — the F1/F2/F5/F7/F8 fixes are real, not veneer: overhead is a named, testable function; the fixture is free-form (test:46) so the `## Project` false positive is gone; order is anchored before `<existing-memory>` (test:72-79); the drop rule is one conditioned sentence; and the five data-path files are byte-identical to `3980099` (sha256 verified), so free-form `MEMORY.md` compatibility is preserved.
