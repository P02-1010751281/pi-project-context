## important

1. **`/handoff budget recent off` 的回执文案声称摘要存在** — `extensions/project-context/handoff/run.ts:435`：「Handoff: summary only, no recent carry-over.」此模式下 successor 实际只拿到文件清单 + 日志指针，**没有任何摘要**。文案把丢数据的模式描述成「内容仍在摘要里」，是本次审查焦点 #2 要找的「看起来有效但无读者」误导的最直接实例。影响：用户据此以为会话内容以摘要形式保留。最小修法：改为「no recent carry-over; the file list and the session-log pointer are all that carry.」（zh 同改），只动这一句。

2. **`/handoff thinking` 回执文案声称摘要调用仍在跑** — `run.ts:452-453`：「Handoff summaries will run without thinking…」/「…will use the session thinking level (may hit the shared token cap)」。摘要链已删（`handoff/summary.ts` 删除，全仓唯一读者消失），`handoffThinking` 只剩写路径（CHANGELOG 与 `docs/configuration.md:118` 都承认）。命令还能写值，回执却描述一个不存在的行为；补全描述 `run.ts:550`「thinking level for the summary」与 `run.ts:549`「the summary budget」同病。影响：TUI 用户被告知一个永不发生的效果。最小修法：回执改为「thinking is kept for dsh profile parity; pi-side handoff makes no model call」一类事实句（键与动词保留，仅文案）。

3. **CHANGELOG 修复条目与自身第一条矛盾，且描述错误** — `CHANGELOG.md:39-40`：「前缀不超一窗且**老侧仍可摘要**时吸附…**中间体积留在摘要**（裁切 + 既有文件索引）。单回合会话不会因吸附而变成「**无可摘要**」而中止。」同一文件的 `CHANGELOG.md:13-24` 已声明「交接不再生成摘要」，被丢弃的中间体积实际留在旧会话日志（`docs/architecture.md:28-31` 才是正确措辞）。影响：发布说明对核心载荷去向给出相反描述。最小修法：把三处「摘要」改成「可丢内容/留在会话日志」（对齐 architecture.md 的表述），只动该条。

4. **状态行换词未同步权威词汇表** — `run.ts:47-50` 状态行现为 ` · drop N` / ` · drop budget N`，而命令面与配置键仍是 `budget summary`（保留拼写是设计决定，合理），但 `.codestable/reference/vocabulary-conventions.md:50` 仍规定「状态行事实词与命令面同词（`summary budget 64k`）」。按 `attention.md` 的硬规则「只改一半算未完成」，本轮改了状态行词却没把规范表改齐（设计 `handoff-last-turn-design.md` §8.4 只记录「待命名决议」，未落到规范表）。影响：下一轮按规范表做事的人会读到一条代码已违反的规则。最小修法：在 vocabulary-conventions.md 增补一条 v0.4.1 分叉词记录（`drop budget` = 状态行事实词，键名保留 pending 决议），一行即可。

8. **注入渲染静默丢弃文档前言** — `shared/inject.ts:48-56`：第一个 `##` 之前的行不属于任何节；一旦存在任何指针，前言（CONTEXT.md 的 `Last updated: <时间戳>`、MEMORY.md 的 `# Project Memory` 标题）被静默丢弃，且 `sections-test.mjs` 无断言钉住。文档字符串只承诺「spec 未命名的**节**常驻」，没提前言；实测本仓 CONTEXT.md 的时间戳已从注入中消失（合成探针确认）。影响：模型失去「上下文新鲜度」信号。最小修法：要么保留前言并入注入，要么在 inject.ts 文档与 CHANGELOG 明说前言被裁。

9. **截断标记可能随 `## Index` 一起被索引掉** — `memory/document.ts:134` 把 `_[memory truncated at …]_` 追加在保留下界之后；`## Index` 是最后一节（`schema.ts:24`），当 cap 裁点落在 Index 节内时，标记随指针被压掉。「被裁的记忆绝不能看起来完整」这一诚实性不变量在注入层降级（模型读到文件时仍能看见标记，故非数据丢失）。最小修法：渲染时把该行视为文档级内容挪出节体，或注入时单独保留。

12. **零模型调用 pin 只在前三幕之后求值一次** — `tests/handoff-test.mjs:721`：`modelCalls === 0` 在 pin 场景后立即检查，后续 orphan/snap/single/big/settings/restore 场景共享同一个 `countModelCall`（`handoff-test.mjs:670-673`），只能靠「调用即抛错 → 该场景断言级联红」兜底；若回归路径把模型调用**吞掉错误后回退**，任何断言都不会红。设计 `handoff-last-turn-design.md` §8.3 的「级联…含 the handoff reaches no model at all」只对第一幕字面成立。最小修法：把 `modelCalls === 0` 的检查移到所有场景之后再断言一次。

## residual-risk（对抗轮）

**最可能的生产 bug：指针是仓库相对路径，而模型 read 工具按会话 cwd 解析。**
证据路径：`memory/injection.ts:24` 断言「injected prompt runs with the project root as its working directory」——这是一条**未经测试的假设**；`shared/inject.ts:62` 渲染的指针是相对路径 `.agents/memory/MEMORY.md`；而扩展自己的 `shared/paths.ts` `getProjectRoot` 用 `git rev-parse --show-toplevel` 从 `ctx.cwd` **向上找根**——代码自己承认二者可能不同；pi 的 read 工具按会话 cwd 解析相对路径（pi-core `dist/core/tools/read.js:56`：`resolveReadPathAsync(path, ctx?.cwd || cwd)`）；审计 §7/§8 的所有探针都在项目根跑，该风险从未被暴露。消费仓若在子目录启动 pi，强指令规定的 read 会 ENOENT——恰恰落回设计 §2 实测过的失败模式（v4-pro 不读时「不声明自己在猜」），或浪费一轮。最小修法：指针里输出绝对路径（注入时已知 projectRoot）。

**次级：锚点依赖 `turnStartIndex` 是 user 条目。** 设计文档自己记录 pi 的 `isTurnStartMessage` 也认 `branchSummary`/`compactionSummary`（`handoff-last-turn-design.md` §2 A）：若被切回合紧跟一次 compaction，锚点可能锚住一个重放层过滤掉的条目（`text.ts` 的 `isReplayableRole` 不含这些角色），起始问题再次丢失、退回 `SPLIT_TURN_MARKER` 兜底。纯推测，需要一次真实压缩后会话的探针验证。
