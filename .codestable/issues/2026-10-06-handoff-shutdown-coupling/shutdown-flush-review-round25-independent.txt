## blocking

### B-1. 缩进的 setext 下划线（1–3 空格）不被当作终止符 ⇒ fail-open

`file:line`: `extensions/project-context/memory/sections.ts:405`（`endsSectionScope` 第二条分支）
`/^(?:=+|-+)[ \t]*$/` 没有前导缩进容忍。CommonMark 的 setext 下划线允许 **最多 3 个空格缩进**（`remark-parse` 实测把 `## Project\nNotes\n   =====` 解析成 `heading depth 1` 的第二个标题）。于是「顶格 `## Project` + 一个缩进 setext 标题 + `- ` 条目」在扫描器眼里仍是「`## Project` 下有一条条目」。

最小复现（我用真实 pass 端到端确认 `MEMORY.md` 被覆盖，不是只测纯函数）：

```
"# Project Memory\n\n## Project\nNotes\n   =====\n- an entry under an indented setext heading\n"
"# Project Memory\n\n## Project\nNotes\n =\n- an entry under an indented single-dash setext heading\n"
```

- 冻结树：`hasMemoryDocumentShape` 返回 `true`，一次 `/memory update` 把上面整段写进 `MEMORY.md`（`e2e.mjs` 输出 `OVERWROTE indented-setext-3sp / 1sp / single-dash`）。
- 与第 23 轮 B-1、第 24 轮 B-2 是**同一个类**：`single-dash-setext-between-entry` 在第 0 列被正确拒绝，同一形状加一个空格就被接受 —— 谓词不一致，方向是放宽侧（接受），按本仓一路的口径属 blocking。

最小修法（CommonMark 精确容忍；`^ {0,3}` 而非 `\s*`，因为 4 空格/制表符是缩进代码块，本就不该重置）:

```ts
return /^\s*#/.test(line) || /^ {0,3}(?:=+|-+)[ \t]*$/.test(line) || /^…HTML…/;
```

验证：打上该修法后 `probe2` 中 `indented-setext-3sp/1sp/single-dash/two-dash` 全部 `REFUSE`，`setext-4sp`（缩进代码块）与 `tab-setext` 仍 `ACCEPT`（正确），`consolidation-test.mjs` 与 `sections-test.mjs` 全绿。

### B-2. HTML 块起始条件只实现了「同行闭合的标签」⇒ 多行标签 / 未闭合 PI / 未闭合 CDATA 仍 fail-open

`file:line`: `extensions/project-context/memory/sections.ts:405`（第三条分支）+ 注释 `:403-404`（「any tag-opening line starts an HTML block」与实现不符）
`/^\s*<\/?[A-Za-z][^>]*>/` 要求 `<` 后紧跟 ASCII 字母且**同一行内**有 `>`。CommonMark 的 HTML 块起始（type 3/4/5/6）还覆盖：`<?`、`<!`、`<![CDATA[`、以及块标签名后直接换行（type 6 允许行尾）。这些行会开启一个吞掉后续内容的 HTML 块，使 `- ` 条目不再是列表项。`remark-parse` 实测：

```
<?php\n- entry        => [html]        （条目被吞）
<![CDATA[\n- entry    => [html]
<h2\n>\n- entry       => [html]
```

端到端确认冻结树被覆盖（`e2e2.mjs`）：`multiline-html-tag` / `processing-unclosed` / `cdata-unclosed` 全部 `OVERWROTE`。而同一批的 `<!DOCTYPE html>` / `<!-- c -->`（单行即闭合，后续 bullet 确是列表）被覆盖是**正确行为**，不应算入。

最小修法（fail-closed，且与本函数既有注释「this extension never writes a line starting with `<`」一致）：把第三条分支放宽为 `/^\s*</.test(line)`；代价是单行 `<!-- … -->` / `<!DOCTYPE …>` 也会重置作用域（多拒几个本扩展从不写的形状，方向安全）。

验证：打上后 `probe2` 中 `multiline-html-tag / processing / cdata` 全部 `REFUSE`，`consolidation-test.mjs`、`sections-test.mjs` 全绿。

> 两条合起来说明第 24 轮 I-1 的「任何标签开启行」是一句**过度承诺**：实现只覆盖了「带字母名且同行闭合」的标签。

## residual-risk（已知边界，修复 B-1/B-2 后仍保留）

- `hasMemoryDocumentShape` 判据仍是启发式，不是 CommonMark 解析器；路线 B 的接受面以「本扩展自己的形状」为准（第 22 轮节具名登记），其余形状的误拒是刻意代价。

- 单行 `<!-- … -->` / `<!DOCTYPE …>` 后面跟 bullet：CommonMark 里 bullet 确实是列表（`remark-parse` 给 `[html,list]`），现实现「接受」是对的；若采用 B-2 的 `/^\s*</` 修法会变成拒绝，属更严的安全方向。
- Unicode 行分隔符已被 `LINE_SEPARATOR_RE` 归一（`\u2028` / `\u2029` 的 setext 实测 REFUSE）；`\u0085` 不是 CommonMark 行尾，单行内不产生新标题，行为正确。
