## blocking

### B-1 `hasMemoryDocumentShape` 不把 setext 标题当作用域终止符（I-1 的 setext 孪生，fail-open）

`extensions/project-context/memory/sections.ts:424-430`

第 22 轮 I-1 的修法是：任何非 `## <已知小节名>` 的 ATX 标题都 `underKnownHeading = false`。但 setext 标题（`Notes\n=====` / `Notes\n-----`）同样是标题、同样开启新小节，闸门却不重置。于是条目被挂到 setext 标题下时，闸门仍认为它在 `## Project` 下，接受整篇回复。

最小复现（存储侧为规范四节文档，回复走 `fallback-opaque`）：

```
# Project Memory

## Project

Notes from the review
=====================
- I will review the frozen revision against the code
```

端到端实测（`tests/consolidation-test.mjs` 的 `project`/`pass` 夹具，逐字节对比）：

```
##### setext-between-entry  changed=true          ← 整篇记忆被换成上面这段
```

对照：同一形状换成 ATX（`# Notes`）在 HEAD 上 `changed=false` 并写 `not a writable memory document`（I-1 修复生效）。`marked.lexer` 对上面这段的判定是 `heading(h2) Project` → `heading(h1) "Notes from the review"` → `list`，即条目确实在 h1 下，不在 `## Project` 下——闸门的契约（`report` 与 `docs/architecture.md:137` 都写「其下至少一条 `- ` 条目」）被违反。这与第 22 轮 I-1 是完全相同的机制，只是标题语法换成 setext；`setext` 反向用例（`consolidation-test.mjs:1956`）因为没有 `## Project` 而恰好绕过了这个缺口。

最小修法（放在 `sections.ts:426-429` 的 ATX 重置之后、`startsWith("- ")` 判定之前）：

```ts
// A setext underline makes the line above it a heading, which ends the section just like an
// intervening ATX heading does (round 22 I-1 was the ATX half).
if (/^(?:=+|-{2,})\s*$/.test(line)) {
	underKnownHeading = false;
	continue;
}
```

`-{2,}` 同时会把裸分隔线当终止符——方向是 fail-closed，安全。同类的 HTML 标题（`<h2>…</h2>` 夹在中间）也被当前实现接受；若一并处理，重置条件再加 `/^<h[1-6][^>]*>.*<\/h[1-6]>\s*$/i`。

建议补两条用例（挨着 `consolidation-test.mjs:1918`）：`setext-between-entry`、`html-between-entry`，断言与 `entry-under-other-heading` 相同（存储逐字节不变 + `not a writable memory document`）。变异（删掉上面的 setext 重置）应恰红这 4 条。

## learning

### L-1 两处围栏预处理差异逐条判定

`isHeadingOnlyDocument`（`sections.ts:303-314`）与 `hasMemoryDocumentShape`（`sections.ts:403-409`）：

| 预处理 | `isHeadingOnlyDocument` | `hasMemoryDocumentShape` | 判定 |
| --- | --- | --- | --- |
| 行分隔符 | 先把 `\r\n?`/`\u2028`/`\u2029` 统一成 `\n`（`:303-306`） | 不统一；只对标题行去尾 `\r`（`:419`），围栏靠 `\s*` 兜住 | **刻意**。方向安全：不统一时 `hasMemoryDocumentShape` 更少识别（回退/拒绝） |
| HTML 注释 | 先删（`:305`） | 不删 | **刻意/无影响**（注释行不构成围栏行、不构成标题/条目） |
| 缩进 | `trim()` 全去（`:307`） | 只去 1–3 个空格（`:408`） | **刻意**。4 空格是缩进代码块（CommonMark 围栏规则，注释就写在 `:404-405`）；两边方向相反是有意的：接受闸门不能过度识别围栏（会 fail-open），骨架闸门过度识别结构是 fail-closed |
| 列表标记 | 读围栏前不剥（从 raw 读，`:311`） | 围栏**外**剥恰好 1 个（`:409`） | **刻意**。21 B-2（`- ```` ` 是列表项里的围栏，不剥就会把 `- ```` ` 当条目而 fail-open）+ 22 B-1（围栏内不许剥） |
| 引用标记 | 不剥 | 不剥 | **一致**（两边都不认引用里的围栏） |

我用 `marked` 做了交叉核对，并 fuzz 了 19 种 opener × 5 种 body（含 `- - ```` `、`> ```` `、`> > ```` `、`- > ```` `、`> - ```` `、4 空格缩进、tab、`1.`/`1)`、`~~~`、info string），**没有任何一例**「闸门 ACCEPT 而 `marked` 把 `## Project` 判进 code」。原因是一致的：闸门不认识的那些 opener 都带容器前缀（`>` 或第二层 `-`），而不带前缀的内容行在 CommonMark 里本来就出了容器、是真正的顶层标题+条目；真正留在容器里的内容（`> ## Project`、四空格 `## Project`）闸门也都拒绝。所以那两处差异本身不是缺口，只是「具名边界」。真正的缺口是 B-1 的 setext 作用域。
