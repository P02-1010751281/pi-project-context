## blocking

### B1. round 3 的 I1 只修了 flush 末尾那次复检，同一读—stat TOCTOU 仍原样留在 `adoptExternalEdit`；更新的手改仍会被写进陈旧 key 并永久压住（数据丢失）
- **file:line**：`extensions/project-context/memory/store.ts:73`（`readOptional`）与 `:76-77`（随后 `stat`）+ flush 调用它的 `:147-150`；对照修复点 `:89-96`（`readRenderWithMtime`）与 `:152-154`。
- **事实/复现**：`adoptExternalEdit` 仍是「先读 render 字节（V1），后 stat（V2）」：判定用的是 V2 的 mtime，写进 journal 的是 V1 的 key。我用 FIFO 把读阻塞住，在读与 stat 之间落地一次外部写（`mkfifo` → 写入 V1 → `unlink` + 建 V2 普通文件 → 关写端），跑真实 `flushMemoryRender`：

  ```
  [control: stable V2 newer than journal] result={"adopted":true,"written":false}  journal V2=true disk V2=true
  [race: V1 read, V2 lands before adopt stat] result={"adopted":true,"written":true}
      journal V1=true  journal V2=false
      disk V1=true  disk V2=false      ← 更新的 V2 从磁盘和 journal 双双消失
  ```

  机制与 round 3 记录的 I1 完全同类：adopt 把 V1（陈旧）当「新」append，`appendMemoryOp` 把 journal mtime 推到 V2 之后 ⇒ adopt 循环第二轮看到 `renderMtime <= journalMtime` 直接返回 false ⇒ V2 再也不会被采纳；随后 flush 的 `readRenderWithMtime` 看到的是稳定的 V2（`changed=false`），但 `renderMtime(V2) < journalMtime` ⇒ 判 `publish`，用 fold(**V1**) 覆盖 V2。修复点 `readRenderWithMtime` 只保护了 flush 自己的这一次读，管不到更早的 adopt 读。
- **影响**：与 round 3 定性一致——journal 被写脏 + 更新的用户手改永久丢失；`store.ts:130-133` 的 docstring「a render the journal has not yet absorbed is journaled and left on disk exactly as it was found」和 `docs/architecture.md:102`「读取期间被替换的文件两者都不动」在该路径上不成立。窗口是微秒级外部写，但 round 3 对等价窗口即按 important 处理并要求修。
- **修复边界**：让 `adoptExternalEdit` 自身的读也走一致性读——当 `preRead.renderKey` 未提供时用 `readRenderWithMtime`，`changed` 就返回 false（不入 journal、不写回，留给下一次 pass）；或在 flush 的决策里同时以 `render.changed`/adopt 的一致性读为准。`recordMemoryDocument` 的 `preRead.renderKey` 路径可维持现状（其 pre-publish recheck 会兜住），但需在注释里写明这是唯一例外。

## residual-risk

- `readRenderWithMtime` 的 `changed` 依赖 mtime+size：同尺寸且 mtime 浮点相同（粗粒度 FS 或同 mtime 重写）时检测不到，属启发式而非内容哈希；不过此时 adopt 的 stat 也会给出同样版本，主要风险仍落在 B1 的 adopt 路径。
- 读期间文件被删（`after` undefined）时 `changed=false`，flush 会 `publish` 重建 fold；这是「缺失即重发」的预期行为，但意味着并发删除会触发一次写与备份。
- 采纳循环结束到 `writeAtomic` 之间仍留有 round 2 已记录的极小窗口（与 `recordMemoryDocument` pre-publish 同级）。
- settle 路仍可用一段对话式回复换掉整篇记忆（round 1 R1 / round 3 现场），本 issue 未覆盖。
