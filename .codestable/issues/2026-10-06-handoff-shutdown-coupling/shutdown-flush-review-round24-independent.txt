## blocking

**B-1. `hasMemoryDocumentShape` 不归一化换行符，CRLF 击穿本轮新增的全部 `$` 锚定终止符。**
`extensions/project-context/memory/sections.ts:410`（循环）/ `:434`（终止符）。本轮把 setext/HTML 终止符写成 `[ \t]*$` / `[ \t]*$` 锚定，但本函数直接 `value.split("\n")`，行尾残留 `\r`；同模块的 `isHeadingOnlyDocument` 恰恰**先**跑 `LINE_SEPARATOR_RE` 归一化，它的 docstring 明说「`$` 锚定的匹配器遇到 `\r` 会被击穿」。于是：

```
# Project Memory\r\n\r\n## Project\r\nNotes\r\n=====\r\n- an entry\r\n   → REPLACED（端到端实测）
# Project Memory\r\n\r\n## Project\r\n<h2>Notes</h2>\r\n- an entry\r\n       → REPLACED
```

`=====\r` / `<h2>…</h2>\r` 不匹配终止符 → `underKnownHeading` 仍为 true → `- entry\r` 命中 `startsWith("- ")`。`isHeadingOnlyDocument` 归一化后认为有正文，两道门都不拦。
最小修法（一行）：`sections.ts:410` 改为
```ts
for (const line of value.replace(LINE_SEPARATOR_RE, "\n").split("\n")) {
```
（`LINE_SEPARATOR_RE` 已在本模块定义；规范文档 `## Project\r\n- entry\r\n` 行为不变，我实测仍为 true。）

**B-2. setext 下划线只认 `-{2,}`，单 `-` 是 CommonMark 的 setext 下划线（与 `=+` 不对称）。**
`extensions/project-context/memory/sections.ts:434`。`## Project\nNotes\n-\n- an entry` 被接受并**替换存储**（端到端实测）；`marked` 把 `Notes\n-` 解析为 `<h2>Notes</h2>`（与 `Notes\n--` / `Notes\n=` 同义）。这正是第 23 轮 B-1「关一种隔断不等于关一类规则」的孪生：`=` 侧用 `=+`，`-` 侧却用 `-{2,}`。
最小修法：`/^(?:=+|-{2,})[ \t]*$/` → `/^(?:=+|-+)[ \t]*$/`。这是 fail-closed（裸 `-` 行本扩展从不写），反向对照（规范 `## Project\n- x`）不受影响。

## important

**I-1. HTML 终止符只认单行严格形式，尾随文本 / 多行 / HTML 块仍 fail-open。**
`extensions/project-context/memory/sections.ts:434`。下面三条均端到端 REPLACED：
```
## Project\n<h2>Notes</h2> trailing\n- entry      （该行起 HTML 块，吞掉后续 - entry）
## Project\n<h2>\nNotes\n</h2>\n- entry          （多行 HTML 标题）
## Project\n<div>\n- entry\n</div>               （HTML 块吞掉条目）
```
本轮既然已决定让 HTML 标题终止作用域、且接受面「只认本扩展自己的形状（从不写 HTML）」，终止条件应是「HTML 块/标签开启行」而不是「恰好一行 `<hN>…</hN>`」。
最小修法：把 `:434` 的 HTML 备选换成 `/^\s*<\/?[A-Za-z][^>]*>/`（或无歧义的 `/^\s*<\/?[A-Za-z]/`）；规范文档的任何行都不会以 `<` 开头，方向 fail-closed。可与 B-2 合并成一次 `:434` 的替换。

## suggestion

- 把终止符判定抽成一个 `endsSectionScope(line)` 小助手，并在其中先做换行归一化，避免 `isHeadingOnlyDocument` 与 `hasMemoryDocumentShape` 再次各自演化出「归一化 / 锚定」不一致（B-1 这类问题的结构性根因）。

## learning

- `$` 锚定的规则在**同模块内**换一个入口就失效：`isHeadingOnlyDocument` 的 docstring 已经把这个坑写下来了，本轮却在它旁边新加了两条 `$` 锚定匹配器而没有复用那段归一化。规则的一致性要落到「输入预处理」这一层，不是每条规则各自记住。
- setext 下划线是 `=+` **或** `-+`；写 `-{2,}` 是凭「`-` 像 bullet」的直觉排歧，而不是按文法排歧。`=`/`-` 的不对称本身就是信号。

## residual-risk

- 即便 B-1/B-2/I-1 修掉，`hasMemoryDocumentShape` 仍是行级扫描而非 markdown 块解析：表格、引用块、缩进代码块、`<pre>` 等「非 schema 但会吞行」的块仍未建模。这些属于第 22 轮登记的「接受面 = 本扩展自己的形状」之外的物理边界；若要收口，应在第 22 轮节具名补登记，而不是留成隐性口子。
- B-1 的输入（CRLF 回复）在真实路由上取决于 provider/模型；`isHeadingOnlyDocument` 明确为它做了归一化，说明作者认为可达。修法是一行归一化，不建议作为长期残留。
