## blocking

### B1. `session_shutdown` 的 catch 会因 `ctx.cwd` 再次抛错而失效，重新制造「异常逃进 ExtensionRunner」那条链
- `extensions/project-context/memory/report.ts:418`（try 第一行）与 `:423`（catch 内两处）：
  ```ts
  try { const projectRoot = await getProjectRoot(pi, ctx.cwd); ... }
  catch (error) { const root = shutdownErrorRoot(await getProjectRoot(pi, ctx.cwd).catch(...), ctx.cwd); ... }
  ```
  `ctx.cwd` 是一个可能抛错的 getter（`report.ts:146` 的 `consolidate` 注释与 `brief.md` 都把它当作既定事实：会话被替换/重载后 `ctx.cwd` 会抛）。回到本次改动：**旧代码的 try 体不直接读 `ctx.cwd`**——`consolidate(ctx, true, true)` 在自己的 try 里读，异常被它吞掉（silent=true），外层 catch 根本不会运行。新代码把 `getProjectRoot(pi, ctx.cwd)` 搬进 handler 的 try 后，`ctx.cwd` 抛错会进入外层 catch，而 catch 又同步读 `ctx.cwd` → **catch 自身抛出**，handler reject，错误逸出到 `ExtensionRunner.emit` / `emitSessionShutdownEvent`。这正是 issue `2026-10-06-handoff-shutdown-coupling` 要消除的失败类（handoff 的 `newSession` 骑同一个 emit）。
- 实测（同一 mock，`ctx.cwd` 定义为抛错 getter，跑 `session_shutdown`）：
  - HEAD：`HANDLER THREW: ctx.cwd: session replaced`
  - `d4d7ed3`：`threw: false`
- 修复边界：在 handler 入口用一次受保护的读取拿到 `cwd`，try/catch 全程只用这个局部值（catch 不得再触碰 `ctx`）；或把 `ctx.cwd` 的读取放进独立的 `try { … } catch { return; }`。

### I4. 「写回在采纳之后因规范化差异触发」这一主张在代码里不成立
`extensions/project-context/memory/store.ts:94-95` 注释与 `shutdown-flush-fix-note.md:23` 都声称：写回「fires after an adoption whose bytes changed under normalization（空白，或手改超帽被裁）」。但 `adoptExternalEdit` 追加的是 `renderKey = memoryComparisonKey(onDisk)`（`store.ts:63-78`），flush 随后用 `memoryComparisonKey` 比较（`store.ts:107`）：采纳一旦发生，`fold` 与磁盘 render 在比较键下**按构造相等**，`written` 永远为 false。实测：
- 空白差异手改（更新 mtime）：`{adopted:false,written:false}`；

### I5. flush 的 render 写回是唯一不带备份的记忆文档写路径

## learning

- 用 `calls === beforeCalls` 去钉「退出不调模型」会被 `forceDedupeMs`(15s) 掩盖：种子与退出相隔毫秒，恒被去重。要钉该性质，必须把退出移到去重窗之外，或观测另一信号（如断言退出只走了 adopt 路径）。
- 「文件仍是 journal 的 render」≠「发生了一次 render 重写」：采纳后两者在比较键下按构造相等，写回分支必须用独立的 fixture（缺 render / 旧 render）才能被覆盖。
- extract-refactor 的等价性可以很便宜地证明：`external-edit-test.mjs` 在 `d4d7ed3` 与 HEAD 都全绿，说明 `adoptExternalEdit` 的抽取与 `renderKey`/mtime 语义保持等价。

## praise

- `adoptExternalEdit` 抽取是严格保行为的：新旧树 `external-edit-test.mjs` 均 ALL OK，`recordMemoryDocument` 的 `renderKey`、`foldedView`、`renderInfo.mtimeMs <= journalInfo.mtimeMs` 比较逐项对齐。
- 代码注释与 `report.ts` 的注册点说明同步更新，`git diff --check` 干净，全套 15/15。
- 新增的 settle 组是有效的：它确实能抓住「agent_settled 被改坏」，突变 B 精确红两条。
