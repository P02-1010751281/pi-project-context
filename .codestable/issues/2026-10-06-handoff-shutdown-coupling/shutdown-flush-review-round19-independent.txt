## blocking

**B-1. The reply-side fence state machine is incomplete: a code block can still be published as a document (fail-open).**
`extensions/project-context/memory/pass.ts:339-347` opens a fence on `^(`{3,}|~{3,})` and closes on the **same character only**; it never compares the opening run length nor checks the closing line's info string. The module's own `isHeadingOnlyDocument` (`extensions/project-context/memory/sections.ts:304`) requires `fence.run.length >= openFence.run.length && fence.info === ""`. The fix's claim at `pass.ts:331` ("Fences are tracked") and `docs/architecture.md:140` / `CHANGELOG.md:17-19` ("围栏内的内容不算文档") is therefore false in constructible cases.

Reproduced end-to-end (real pass through `/memory update`, canonical four-section store, reply body > 40 chars — all `REPLACED`):

```
# Project Memory

````
code
```
## Project
- <entry>
```
```
→ REPLACED   (4-backtick opened, 3-backtick closes it early; CommonMark keeps it open)

# Project Memory

~~~~
code
~~~
## Project
- <entry>
→ REPLACED   (same for tildes)

# Project Memory

```
prose
```not-a-close
## Project
- <entry>
→ REPLACED   (closing fence with an info string is not a closing fence)
```

Impact: fail-open — the whole stored memory is replaced by the code sample. This is exactly the R-A/I-2 class the round-18 fix was added to close, so the fix is incomplete, not a new feature. Fix boundary: store `{char, run}` on open and close only when the line's run length is `>=` the opening's and its info string is empty — i.e. hoist/export the predicate from `sections.ts` and call it from both sites (the repo already mandates a single decision point for `peekAuxModel`; the same reasoning applies here).

**B-2. A bare `=` / `--` / `---` line counts as a "heading", so a conversational separator + bullet is accepted as a document (fail-open, new regression).**
`pass.ts:348` tests `/^=+[ \t]*$/` and `/^-{2,}[ \t]*$/` as heading markers. A setext heading is a *text line underlined*; a standalone `---` is a thematic break and a standalone `=`/`--` is a paragraph, not a heading. `docs/architecture.md:139-140` and `CHANGELOG.md:17-18` sell this as "setext 下划线 / 至少一个标题".

Reproduced (real pass, `REPLACED` at HEAD; the same inputs were **refused** at the round-18 frozen revision `63a825f`, i.e. this is a regression the fix introduced):

```
# Project Memory

---
- <a 78-char sentence>
→ HEAD: REPLACED   (63a825f: kept)

# Project Memory

=
- <same sentence>
→ HEAD: REPLACED   (63a825f: kept)

# Project Memory

--
- <same sentence>
→ HEAD: REPLACED
```

Impact: trivial fail-open; a terse reply with a horizontal rule and one bullet overwrites memory, and the diagnostic never fires because `replyIsDocument=true` short-circuits `isHeadingOnlyDocument`. Fix boundary: make the `=+`/`-+` line a heading only when the previous non-blank line is a non-empty text line (the module's model: the underline marks the line *above* it); otherwise treat it as a separator. Add the reverse test (`---`/`=`/`--` + bullet must be **refused**), which the current suite lacks (the reverse tests only cover the shapes named in the finding).

## suggestion

- Add the two missing negative cases (B-1/B-2). They are the only holes I found and the suite is green on both.
- Extract the fence parity into one exported helper in `sections.ts` and consume it from both `isHeadingOnlyDocument` and the reply scanner, so the "same family" half can never be copied without the run-length/info-string half again.

## learning

- A state machine cannot be mirrored by half. The fix kept CommonMark's "same family" rule and dropped its run-length and info-string rules; the module already had the full predicate one file away.
- "Recognize the module's vocabulary" for setext was implemented as "a line of `=`/`-`" rather than "a text line underlined by `=`/`-`". A vocabulary is a grammar, not a character set — that is how `---\n- x` slipped through.
- The round-18 reviewer predicted the exact failure mode (unidirectional tests: only the shapes named in the finding are tested). The reverse tests cover numbered/setext/HTML but not the separator/longer-fence variants, so the suite stays green over the holes.
