## 发现

### 1. `replayMessagesFor` 的 JSDoc 重复（minor）
- **文件:行**：`extensions/project-context/handoff.ts:337-343` 与 `:344-354`
- **问题**：本轮增量在原注释上就地改写（337–343），又**新增**了一块几乎相同的注释（344–354），两块紧贴同一 `export function`。第一块内容已被第二块完全覆盖，成为死注释；TS 会把两个块都当文档注释，实际附加给符号的是最后的块，前者纯属噪声，也容易让后续读者误以为有两个不同语义段落。
- **建议**：删除前一块（337–343）。
- **证据**：`git diff HEAD -- extensions/project-context/handoff.ts` 头部——`-export function replayMessagesFor(entries: SessionEntry[]): AgentMessage[] {` 处新增了一个 `/** … */` 块，而原块仅被改写保留；`awk` 输出确认两块 337/344 起头、正文逐字相同。

### 2. 切点注释仍复述第 3 轮被证伪的前提（minor）
- **文件:行**：`extensions/project-context/handoff.ts:826-830`（另 `:325-327` `SPLIT_TURN_MARKER` 注释）
- **问题**：注释写「pi's cut points never sit on a tool result, **so a kept result always follows its call**」。这正是第 3 轮 m1 证伪的命题：当 `branch_summary` 插在「带 toolCall 的 assistant」与其 toolResult 之间时，切点可落在 `branch_summary` 上，kept result 的 call 就留在前缀里。本轮新增的 `droppedOrphans` 折入正是为处理该形状——注释却仍断言它不会发生，与紧随其后的实现自相矛盾。
- **建议**：把该句改为「切点不在 toolResult 上，但可落在 summary 条目上而把某个 result 与其前缀中的 call 分开；这种孤儿结果由 `droppedOrphans` 收进摘要」（即引用新机制）。
- **证据**：`findCutPoint(entries,0,len,8)` 在 `[u1, a1(toolCall), branch_summary, toolResult, a2, u2]` 上得 `firstKeptEntryIndex=2`（落在 `branch_summary`）→ kept=`[branch_summary, toolResult(call 在前缀), …]`。

### 3. `estimatedAfter` / `baselineNow` 对孤儿结果**双重扣减**（minor；当前路径不可达）
- **文件:行**：`extensions/project-context/handoff.ts:847-851`（折入）、`:865-866`（`olderTokens`/`sliceTokens`）、`:900-901`（`baselineNow = usage.tokens - olderTokens - sliceTokens`）
- **问题**：折入把 `droppedOrphans` 追加进 `olderMessages`，于是 `olderTokens` 含孤儿；而 `sliceTokens` 来自 `carriedMessages = keptSlice.flatMap(...)`，**本就含同一孤儿**（孤儿来自 keptSlice）。`baselineNow` 因此把孤儿 token 从 `usage.tokens` 里扣了两次，`estimatedAfter` 被低估恰好一个孤儿量（实测大 toolResult 时 ≈10k token）。方向是让跳过闸门**更松**（更倾向交接），且 `olderTokens` 还参与 `MIN_SUMMARIZE_TOKENS` 下限，口径不一致。
- **当前影响**：`runHandoff` 仅有两个调用点（`:1175` `now/run/force`、`:1179` `force-auto`），二者 `force===true`，故 `:897` 的 `!force &&` 闸门与 `:900` 的 `estimatedAfter` 判断当前为**死路径**——此偏差暂不可达。若日后新增非 force 触发即会生效。
- **建议**：`olderTokens` 用「折入前」的 older 计算（另存变量），或把 `estimatedAfter` 改为 `usage.tokens - olderTokensPrefix - sliceTokens + keptTokens + summaryTokens + 1500`；至少加注释说明孤儿只应扣一次。
- **证据**：`/tmp/probe_acct4.mjs`（真实 `findCutPoint`+`replayMessagesFor`）在 cut 落在 `branch_summary`、孤儿 10000 token 时打印 `TRUE baseline 1000000 -> correct estimatedAfter 1002012, post-fix 992012, offset 10000`。

### 4. 折入只清**头部**孤儿，切片中部仍有悬空 toolResult（minor；可达性低）
- **文件:行**：`extensions/project-context/handoff.ts:367-370`
- **问题**：`while (messages[0]?.role === "toolResult")` 只丢开头连续孤儿。若被保留的 user/assistant 消息之后仍有一个「call 在前缀」的 toolResult（`[user, toolResult(orphan), assistant(toolCall), toolResult(paired)]`），该孤儿会原样留在回放里，成为无匹配 call 的悬空结果（strict provider 可能 400），且不会进 `droppedOrphans`。要触发需要「call 与 result 之间插入 user/custom/bashExecution 之类可切条目」的非常规条目序，真实会话中不易出现。
- **建议**：若想彻底，可对「无匹配 call 且不在调用其前缀/本切片」的 toolResult 一律收集并从回放移除，而非只看头部。
