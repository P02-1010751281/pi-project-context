## Findings

### Important

**I-1. A record dropped by the interval-consistency rule loses its `unreported` output, and the next accepted record can falsely re-anchor.**
`extensions/project-context/handoff/threshold.ts:402-403` (drop paths at 394-403; allowance at 421-422)

The allowance credits only `previous.unreported` (the previous *accepted sample*) plus images. A record dropped by the consistency rule (`chars − prev.chars > (prompt − prev.prompt) × 8`, the replay-landing shape of fixture 4c) carries its own billed reply — including hidden output — into every later prompt, but its `unreported` is never stored, so the next accepted record compares `prompt_r − prompt_p` against `2×(chars_r − chars_p)` without credit for that hidden output.

Reproducible probe (frozen code): sample A (17,766), a 200-CJK-char replay lands, record B billed stale at 17,766 with `output: 2,001` (dropped), record C billed at 20,168. Result: **baseline 20,117, sampleIndex 1** (false re-anchor); the control without the dropped record reads **17,766, sampleIndex 0**. The reset re-adds the whole text over-read — the exact ratchet this change fixes, in a bounded, one-shot composite shape (needs a dropped record *and* unreported output on it *and* a tight following interval). Direction is fail-closed (reading raised), bounded by the dropped reply's hidden output; it sits precisely in the handoff-successor first interval this issue is about, but it does not affect the three field sessions (they resolve). The density-floor drop path (394) has the same loss.

Fix boundary: on the two drop paths, carry the dropped record's own `max(0, output − tokens)` into the pending allowance (alongside `entryImages`), e.g. `imageAllowance += entryImages + Math.max(0, (record.output ?? 0) − tokens)`; the compaction-invalidation path needs nothing (split-guarded). Alternatively register the shape as a named residual in the fix note and doc block. Do not touch the sample push or the comparison itself.

**I-2. The doc block inverts the fail-open mechanism.**
`extensions/project-context/handoff/threshold.ts:280-281`

"its false positives only raise the reading, and an **under-counted** allowance reads the baseline low by that reply's hidden output" — an under-counted (too small) allowance makes the detector fire *more*, and a reset raises the reading (probe: allowance removed → 17,767 → 26,780). It is an **over-counted** allowance — one covering output the next prompt does not actually carry (the non-echoing provider, correctly described in the fix note's residual list) — that misses resets and reads the baseline low. This is the repo's characteristic defect class (a sentence stating the opposite of what the code does), newly introduced here. The magnitude bound ("bounded by the reply") is correct.

Fix boundary: reword the sentence to name the over-allowance/non-echoing shape (the fix note's wording is already right); code unchanged.
