## Findings

### N1 (nit) — trim-empty sources are still rewritten on every refresh; missing from residuals
`extensions/project-context/archive/session-log.ts:235-249`; `fix-note.md:62-69`.
Evidence: probe P5 — `"   \n"` source, three consecutive refreshes change the archive inode each time (`204840 → 204841 → 204842`). No cursor is registered now, so `!appended` is entered every call and `writeAtomic` runs each refresh; pre-`42f0956` code no-op'd after the first write. No corruption (content is re-synthesized). Impact: pointless writes/mtime churn for the pathological whitespace-only/unreadable case and a behavior difference vs. pre-fix. Minimal boundary: list it explicitly in §3 residual, or skip `writeAtomic` when the synthesized `raw` equals the current archive.

### N2 (suggestion) — `if (probe === 0) return true` is redundant for correctness
`session-log.ts:86-87`. Removing it (m7) changes nothing: `readBytes(..., 0)` returns `Buffer.alloc(0)` and `equals` is true; the branch only saves two file opens. It is not a live guard that needs pinning, so the residual list need not include it — but a comment saying "skip the two opens" would be clearer than an unexplained early return.

### N3 (suggestion) — the accepted 256-byte blind spot has no characterization test
`session-log.ts:85-98`; `tests/sync-test.mjs:272-292`; `fix-note.md:64`. Round-2 option (a) also asked for "a tail-preserving rewrite test that pins the documented bound". Probe P1 shows that a same-inode, same-size rewrite changing byte 0 of a >256 B field leaves `archive === source` false, and the next refresh does not heal. Impact: a future change to `BOUNDARY_PROBE_BYTES` or the guard could silently broaden the accepted hole with nothing naming the bound. Minimal boundary: add a test that performs an early-byte rewrite with a >256-byte identical tail and asserts the archive is (documented as) stale, or note "no test pins the bound" in §3.

### N4 (suggestion) — residual "unpinned guards" list is incomplete
`session-log.ts:89-98,246`; `fix-note.md:65-66`. Besides `readBytes`/`if (tail)`, the probe catch (m8 `catch→true`) and the `fromSource` cursor-registration condition (m9 registering trim-empty cursors) both survive the full suite. They are defensive/behavioral branches, but the note implies only two such branches exist. Minimal boundary: extend the residual bullet.

### N5 (residual-risk) — probe failure on an unreadable source routes to the destructive rebuild
`session-log.ts:95-97,235-244`. P4: after cursor establishment, `chmod 000` on the source makes `appendBoundaryIntact` return false, and the rebuild path's `readOptional` yields `""`, so the raw archive is **replaced by the synthesized header+entries**. rev14 rejected and left the archive intact. This is the behavior round-2 S2 asked for, and it self-heals once the source is readable again, but temporary source read errors can transiently degrade the raw copy's fidelity. Minimal boundary: record this in §3, or distinguish "source vanished" from "source unreadable" (e.g., probe only the archive side / preserve an existing archive when `readOptional` fails on a non-empty source).

### N6 (nit) — §1's absolute "archive is always a byte prefix of source" claim needs UTF-8 scope
`fix-note.md:23-26` vs. `:68-69`. The residual bullet correctly says a split decode can produce U+FFFD; §1 states the precondition absolutely. P6 confirms it self-heals after the codepoint completes. Minimal boundary: append "(valid UTF-8; see §3)" to §1.
