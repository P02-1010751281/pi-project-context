## 对 Q1/Q2/Q3/Q4 的直接回答（只写我验证到/推断的）

**Q1 阈值预算自洽性：自洽。** 各单位统一为 tokens，作用域明确（`window`/`usable`/`share`/`floor` = 会话窗口；`prefixRoom`/`summarizerWindow` = 摘要模型窗口，这是刻意的跨模型修正）。`cap()` 相对原 `Math.min` 语义等价：tier/usable 两处 `cap` 与原 `Math.min` 逐位等价（`min(x,x)=x`，严格 `<` 与 min 的非严格在结果上一致），`bound` 纯增量；`tokens < floor` 提前返回、`usable <= floor` 早退均原样保留。summarizer cap 因 `prefixRoom = max(MIN_SUMMARIZE_TOKENS, …)` 恒 `≥ floor`，故 I1 修复后它**永不**触发 `tokens < floor` 返回 undefined（这是 I1 的正确落点）。

「40% 下限」被压制（`share` 不再是最终值）只发生在三种情况：小 aux 窗口（`bound=summarizer`）、首个计价档低于 0.4×window（`bound=tier`）、`baseline+keep` 极窄时（`bound=usable`）。三者在 `status` 都通过 `capSuffix` 可见（`· capped by …`），**不再静默**——但见 minor#3，tier/usable 的可见性尚未被测试咬住。

**Q2 交接后模型是否静默回 default：这段代码（`stageHandoffSessionSettings`/`restoreHandoffSessionSettings`）本次 diff 一字未改**（`git diff` 该区域 0 行），属既有行为；测试已覆盖 reason 不匹配、foreign predecessor、TTL、resume、已匹配设置、`setModel` 返回 false、model 未注册等几乎所有分支。唯一「不报错也不恢复」的静默路径是 `event.reason !== "new"`（`handoff.ts:488`）与 `!event.previousSessionFile`（`handoff.ts:488`）——两者都先于任何 notify 静默 return，且**不会清掉已 stage 的文件**（clear 只在 reason==="new" 分支内执行）。真机里 `previousSessionFile` 字符串（绝对路径）是否与 `stage` 时 `getSessionFile()` 逐字节相等、以及 handoff successor 的 reason 是否恒为 `"new"`，本沙箱无法实证（无 model_change JSONL、无 live session），标**推断**。
