## 2. Findings

### blocking

#### B-1R5 自愈判定仍可在健康记忆上静默、破坏性重写（单行前缀 + 嵌套字段两个向量）

**证据**

- 前缀判定（`extensions/project-context/project-state.ts:383-391`）：
  ```ts
  const POISON_PREFIX_LIMIT = 40;
  function isPoisonPrefix(prefix: string): boolean {
    const trimmed = prefix.trim();
    if (!trimmed) return true;
    if (trimmed.length > POISON_PREFIX_LIMIT) return false;
    return /^(?:json|JSON)$/.test(trimmed) || !/[\n#*]/.test(trimmed);
  }
  ```
  非空前缀只要求「≤40 字符、不含 `\n`/`#`/`*`」。因此 `- 事实`、`1. 事实`、`> 事实`、任意单行散文、CRLF 行都通过；而对象前的内容在 heal 时被整体丢弃（`project-state.ts:421-437` 只用 `field.value`）。
- 实测（`/tmp/rev5-probe/heal.mjs`）：
  - FP1：`# Project Memory\n\n- IMPORTANT never run migrations in prod\n{"memory_markdown": "# Project Memory\\n\\n## Sample\\n- documented reply format", "context": {}}\n` → 磁盘被重写为 `# Project Memory\n\n## Sample\n- documented reply format\n`，durable fact 消失，仅 1 个备份、无通知；
  - FP3（`1.`）、FP4（`>`）、FP6（未闭合示例）同样命中；CRLF 变体同样命中（`heal2.mjs`）。
- 端到端（`/tmp/rev5-probe/inject.mjs`，`before_agent_start` 真实注册路径）：`injected has durable fact: false`、`injected has sample: true`、磁盘 `has durable fact: false`——真实事实同时从 system prompt 与 `MEMORY.md` 消失。
- **二次级联**（`/tmp/rev5-probe/cascade.mjs`）：poison 恢复出的记忆若为「单行 bullet + 完整示例」，第一次 `loadMemory` 自愈后，第二次 `loadMemory` 会对刚写出的 Markdown 再自愈一次并丢掉 bullet；两次共 2 个备份，全程无 warning。即无需人工构造特殊文件，poison 派生内容即可触发。
- **嵌套字段向量**：`readJsonStringField(scope, "memory_markdown")`（`project-state.ts:432`）不校验匹配键是对象顶层成员。`{"real_fact": "KEEP", "inner": {"memory_markdown": "# Project Memory\\n\\n## Nested\\n- inner"}}` 顶层前缀为空即命中，`real_fact` 被丢弃（`heal2.mjs` nested-key）。这与 analysis §5-A.2 的「仅匹配结构性顶层 JSON … 正常记忆不得误判」直接冲突。
- **测试假保证**：`tests/consolidation-test.mjs:178-187` 只覆盖多行前缀（`## Notes\n- keep me`），单行前缀与嵌套形态无夹具；变异 M16（`POISON_PREFIX_LIMIT` 40→400）全绿，说明长度上限也没被断言锁定。

**影响**：`loadMemory` 是注入、consolidation、autolearn、`/memory` 的共享读路径，命中即健康记忆被静默替换，只能靠人工发现 `.poison-backup-*`；这是本 issue 的核心数据完整性约束（round 2/3/4 的同一 blocking 类）。

**建议修复边界**

1. 要求匹配到的 `memory_markdown` 是对象 **depth 1** 成员（用 `jsonObjectEnd` 同款字符串感知扫描记录 depth，或在 `[objectAt, objectEnd)` 内验证键前 depth 为 1）。
2. 「对象前」只允许真正的 wrapper：空、围栏/JSON-ish token（` ``` ` / ` ```json ` / `json` / `[`），拒绝所有行首 markdown 结构（`-`、`*`、`+`、`> `、`N.`）与多行/散文；或对字段值占全文比例加守卫（真实 poison 的值≈全文，示例明显不是）。
3. incomplete 分支同样受上述约束（当前 FP6 已证明）。
4. 补固定反例：单行 bullet/numbered/quote/CRLF、嵌套键、二次级联，断言「文件字节不变 + 备份数不变 + 注入内容保留真实事实」。

### important

#### I-S2R CAS 不是原子校验，并发写者仍会被 healed 旧内容覆盖

**证据**：`extensions/project-context/project-state.ts:443-444`
```ts
if (await readOptional(target) !== raw) return current;
await writeAtomic(target, healed);
```
两次 await 之间仍是 TOCTOU；`writeAtomic` 内部还有 `mkdir → writeFile → rename` 三个 await（`project-state.ts:178-188`）。
`/tmp/rev5-probe/race.mjs` 用 `fs.promises.readFile` 钩子在「CAS 读之后、heal rename 之前」确定性插入竞争写：`NEW memory survived: false`，healed 旧内容覆盖新记忆，只留 1 个备份。round-4 的 500/500 大窗口（备份写入期间）已被收窄到读→rename，但没有关闭。变异 M4（删除 CAS 行）整套测试全绿，说明 CAS 本身也无测试覆盖。

**影响**：两个 pi 进程/会话共用一个项目时（本 issue 现场即有两个旧进程），低概率整份覆盖刚写入的新记忆；自愈失败静默。

**建议修复边界**：用排他 claim（`open(..., "wx")` 或 `mkdir` 锁）串行化自愈；或引入真正的 compare-and-swap 原语（如先 `link` 到唯一临时名、确认后再 `rename`；或校验 inode/mtime 且接受仍非原子的事实）。至少要补并发测试，并在 fix-note 明确残余窗口与取舍。

#### T-1R 预算测试仍缺「≤实现 budget」与「回流额度」断言

**证据**：`tests/consolidation-test.mjs:257-266`
```js
const sentLength = () => call.prompt.slice(call.prompt.indexOf("<existing-memory>"), call.prompt.indexOf("</existing-context>")).length;
check("a tiny cap bounds the artifacts sent", sentLength() > 0 && sentLength() <= 1400);
check("the smallest cap still sends memory content", ... sentLength() <= 1024);
```
上界用模型 cap（1400/1024），且 `sentLength` 还包含 `<existing-memory>`/`</existing-context>` 标记；`near` 用例只覆盖 cap=8192 的剪裁。独立变异：**M6（删掉 `contextLimit2` 回流，`consolidate.ts:188-189`）整套测试全绿**——小 memory + 大 context 场景下实现发 365 字符 context，M6 只发 200 字符、留下 ~165 字符预算闲置，无断言发现；M5（删随机备份后缀）全绿。

**影响**：预算回流这一 round-4 important 修复本身没有回归保护；未来改坏预算分配仍可能全绿。

**建议修复边界**：导出 `fitMemoryInput`/`replyTokenRate` 做直接单测，或在测试内用实现公式计算期望 budget，断言 `sentMem + sentCtx ≤ budget`、小 memory 时 context 得到 `budget - memoryUsed`；补 cap=256/1424 边界与回流断言。

## 3. Test And QA Focus

**QA 必须重点复核**

1. **自愈误判实机**：构造「单行 bullet/numbered/quote/散文/CRLF + 末尾完整 sample」与「嵌套 `memory_markdown`」的 `MEMORY.md`，跑 `before_agent_start` 注入、`/memory`、autolearn、automatic consolidate；断言文件字节、备份数、注入内容均不变，真实事实保留。
2. **二次级联**：poison 恢复出的记忆再含「单行 + 完整示例」，连续两次 `loadMemory` 后断言事实仍存在。
3. **并发/时序**：两个 pi 进程（或 `race.mjs` 式确定性交错）复测 heal vs consolidate 写盘窗口；确认新记忆是否被覆盖，并检查 claim/备份行为。
4. **cap 矩阵**：`maxTokens ∈ {256,1024,1025,1400,1424,2048,3685,8192}` ×（大/小 memory，大/无 context）跑 `/memory-learn` 与 automatic；断言 memory/context 非空（源非空时）、`sentMem+sentCtx ≤ 实现公式 budget`、小 memory 时 context 得到剩余额度、不出现 `(none)`。
5. **真实数据夹具**：三份 `/tmp/rev2/real/*` 纳入固定回归（期望 15055/14385/14525）。
6. **真机 headless**：`-p`/`--json` 下 automatic/shutdown/命令三路径 errors.log 均有 `shortened`。
7. **errors.log/备份治理**：长期 clipped 的增长与 1MB 轮转、备份清理策略。
