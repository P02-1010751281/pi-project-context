## 3. important

**I-1 陈旧锁夺取没有所有权判别：原持有者的 `finally` 会删掉新持有者的锁，互斥失效。**
`project-state.ts:256-274`（`tryLock` 写 pid 后无 token 校验，`finally` 无条件 `rm(lockPath)`），夺取逻辑 `:263-265`。复现（加速时钟，等价真实 >30s）：A 持锁在 action 内 → `utimes` 老化 → B 夺取并进入 → A 结束 `finally` 删除的是 B 的锁 → C 立刻进入，`B` 仍在临界区，探针输出 `A-enter / B-enter / A-exit / lock-exists=false / C-enter`。影响：任何一次临界区超过 30s（慢 NFS、挂起恢复、调度停顿）后，「备份读取→修剪→改名」的串行保证失效，可能出现互相覆盖式丢更新（rename 原子，不会写坏字节；备份名唯一，prune 不删新鲜项）。README.md:69 与 fix-note:156 宣称「安全夺取」，实际不成立。修复边界：锁内容写唯一 token（pid+random），释放前读回比对，只在 token 匹配时 `rm`；夺取时用 rename 到自己的唯一名再创建，或比对观察到的 token 后再删；不要只凭 mtime。

**I-2 `clipText` 可返回 `limit+1`，导致 round-11 的「精确修剪」空转，严格预算残差仍在。**
`consolidate.ts:227-229`：当 `text.charCodeAt(tailStart)` 是低代理时 `tailStart -= 1` 以保完整代理对，但未补偿长度，输出由 `limit` 变 `limit+1`（头部减 1 只抵消了 head 侧的另一分支）。于是 `consolidate.ts:307-318` 的 exact trim 用 `clipTo(text, len-1)` 时可能得到同长字符串，4 次迭代零进展。确定性复现：`clipText("aaaaaaaaaaa\n\n😀aaaaaa"…)`，L=20 返回 21 字符；`fitMemoryInput` 60k 随机网格（含 emoji/西里尔/阿拉伯/引号反斜杠）在 0.001 容差下 **254/60000 越界，worst=0.400 token**（集中在 `maxTokens=1024`、`budget=400` 的代理对边界案例；我的随机捕获 case 里 `limit 446 → 输出 447`）。影响：`tokens + reserved ≤ maxTokens` 这一 fix-note 宣称已收口的不变量仍可被打破（≤~0.5 token，不会击穿 provider 上限，仅内部预算/裁剪保证失真）；同时 `clipText` 的「不超长」契约被违反。修复边界：tailStart 因低代理递减时同步把 head 减 1（或改为丢弃孤立低代理 `tailStart += 1`），并在仓库预算矩阵里加入含 emoji 的 fixture 断言 `tokens+reserved ≤ cap+0.001` 与 `clipText().length ≤ limit`。

## 6. learning

- 锁夺取必须做**所有权判别**（token/inode），仅凭 mtime 判断「陈旧」会把活锁当死锁；夺取后原持有者的无条件释放会连锁破坏互斥。
- surrogate-aware 裁剪有两个独立不变量：不产生孤立代理 **和** 不超长；边界修补必须等量补偿，否则会反向破坏精确修剪这类以长度为前提的收敛逻辑。
- 解码召回放宽（单行前缀/context 先行/无 header 值）时，约束组合（全文剩余 + 首键 + 文档形状）能挡住嵌套/短值示例，但「示例本身就是完整文档」在无磁盘标记下不可判别——mode B 的读不写使该残余可接受，写前备份是最后防线。

## 8. residual-risk

- I-1 的触发条件（>30s 临界区）在本地/正常 FS 上罕见，但慢盘/挂起下会真实发生；后果是丢更新而非字节损坏。
- I-2 将严格不变量越界从 0.4 降到 0 的修复未闭环；实际影响 <0.5 token，provider 上限一般不被击穿。
- 无磁盘标记下「整文件是 JSON 示例」仍会被当成污染解码（读写路径有备份兜底）；真实 provider 对抬高 cap 的接受度、真实 tokenizer 与 `replyTokenRate` 的偏差、Windows/NFS 的 rename/mtime 行为均未在沙箱验证。
- 一小时内备份数上界 = 该小时写入次数 + 5（设计使然，高频写入会有临时磁盘占用）。
