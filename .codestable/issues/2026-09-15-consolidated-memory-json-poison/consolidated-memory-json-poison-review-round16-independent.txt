## Nit

1. **N16-1 锁路径本身是非普通文件时仍会永久冻结协议（N15-1 同类问题只修了 `.steal`）** — `project-state.ts:236-253`（`tryLock` EEXIST 直接返回 undefined）、`304-315`（`rm(lockPath,{force:true})` 对目录抛 EISDIR 被吞）。
   - 事实：探针 `/tmp/rev16-probe/probe3.mjs` 预置 `MEMORY.md.lock/` 目录后，写入 5039ms 超时，目录残留，之后每次都超时；而同样形态的 `.steal/` 已能自愈。影响：项目内所有记忆写入在 5s 后失败（fail-safe、无数据丢失），需人工删目录才能恢复。
   - 修复边界：在 `tryLock` 的 EEXIST 分支 stat 锁路径，`!info.isFile()` 时按 `acquireClaim:280-288` 同款 `rename(...broken-<rand>)` 后重试一次；普通陈旧文件仍交给 steal 逻辑，不要动正在使用的锁文件。
2. **N16-2 跨进程子进程与 `run-all.mjs` 都没有 timeout** — `tests/consolidation-test.mjs:739-743`、`tests/run-all.mjs:14`（`spawnSync` 无 timeout）。影响：锁协议若回归成死锁，CI 会永久挂起而非失败。修复边界：`spawn(..., { timeout: 15000 })` 并 kill/reject，或 `Promise.race`；`run-all.mjs` 加 `timeout`。
3. **N16-3 子进程脚本路径用 `URL.pathname` 而非 `fileURLToPath`** — `tests/consolidation-test.mjs:738`。影响：仓库路径含空格/百分号/非 ASCII 时子进程找不到脚本（当前路径安全，属可移植性隐患）。修复边界：`fileURLToPath(new URL("./helpers/lock-holder.mjs", import.meta.url))`。
4. **N16-4 跨进程用例后没有断言锁文件无泄漏** — `tests/consolidation-test.mjs:744-754` 只解析日志。影响：泄漏 `.lock`/`.steal` 不被这条用例发现（后续用例偶然覆盖）。修复边界：追加 `readdir(dir)` 断言不含 `MEMORY.md.lock`/`.steal`。
5. **N16-5 仓库根 `.gitignore` 的 `*.lock` / `errors.log` 过宽** — `.gitignore:6-9`。影响：未来若引入 `yarn.lock`/`Cargo.lock` 等会被静默忽略；本地产物规则本可限定到 `.agents/`。修复边界：改成 `.agents/**/*.lock` 等或仅保留 memory 目录内运行时 `.gitignore`。
6. **N16-6 `.broken-*` 无回收策略** — `project-state.ts:286` 只 rename、不清理，`cleanStaleTemps` 仅匹配 `*.tmp`。影响：每次有非文件占据 claim 路径就新增一个（已被 `.gitignore` 忽略），外部反复制造才会累积；有界但无回收。修复边界：在 `cleanStaleTemps` 或 claim 自愈时顺带按 mtime 清理旧 `.broken-*`。

## Learning

- claim 只保护「取得 claim 的分支」；同理，「非普通文件是文件协议盲点」这一结论对 `<lock>` 与 `<lock>.steal` 同等成立——round 15 只修了 claim 一侧，锁路径一侧仍是同一盲点。自愈应作为**协议入口的统一预处理**，而不是某一个辅助路径的补丁。
- `lockMtimeMs` 的 fail-closed（不可读=Infinity）用「可恢复性」换「不误夺活锁」：对 ELOOP/EACCES 类锁会退化为永久 5s 超时，这是明确记录的取舍，不是 bug。
