# Project Memory

## Project
- pi-project-context: TypeScript/ESM pi coding-agent extension suite — durable project memory, session context, archiving, autolearn, handoff summaries.
- Stack: Node.js, `fs/promises`, `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`. Tests are plain `.mjs` run by `tests/run-all.mjs`; full suite 14/14.
- Layout: `extensions/project-context/` with `memory/` (`document.ts`, `schema.ts`, `context-schema.ts`, `sections.ts`, `report.ts`), `autolearn/` (`schema.ts`, `pass.ts`, `parse.ts`, `evidence.ts`), `handoff/` (facade `handoff.ts` re-exports), `shared/` (config, llm, call-policy, project-state facade, paths, limits, files, notify, redact, lock, gitignore, error-log, migrate, text, output-budget, conversation), `archive/`.
- Rendered state lives under each project's `.agents/memory/`.
- `.codestable/` stores issue reports, reviews, fix notes, release evidence. Preserve `.codestable/features/2026-09-15-codex-project-context-port/` and the four issue dirs listed in Index; the structured-output issue dir holds the frozen design doc, 12 design 审/校 prompt/transcript pairs, 2 code-review prompt/transcript pairs, and `implementation-note.md` (deviations + review trail).

## Invariants
- `README.md` is a concise entry point; details live in `docs/`. `docs/architecture.md` carries the annotated module tree and must list new shared modules.
- Docs and user-facing writing use Simplified Chinese; commit messages use English Conventional Commits (`type(scope): imperative summary`).
- Adaptive-threshold review playbook: `.agents/skills/pi-project-context-adaptive-handoff-threshold-review/SKILL.md`. Cross-cutting protocol/boundary changes use `.agents/skills/pi-project-context-sandboxed-independent-review`, run as 审/校 pairs over a read-only `/tmp` copy; zero writes proven by baseline `git status --porcelain -uall` + `stat` snapshots; each round's prompt/transcript kept in the `.codestable` issue dir. Multi-round work = repeated pairs until every round returns `VERDICT: PASSED`.
- When a shared formula or budget constant changes, sweep every carrier in one pass (docs plain-text + LaTeX + bullets + examples, code comments, test section comments); mark superseded fits in `.codestable` as historical.
- Independent-review findings must be answered with a fix or an explicitly bounded residual written into the fix note; unpinned defensive branches are acceptable only when listed as such.
- `.agents/memory/memory.jsonl` is the append-only source of truth; `MEMORY.md` is the derived render and external-edit entry point. Records are `replace` or `append`.
- `loadMemory()` is the shared read path and distinguishes missing, unreadable, damaged, poisoned, and journal-backed memory. Consolidation fails closed on unparseable model replies.
- External `MEMORY.md` edits are adopted only when normalized content differs from the folded journal and the render is newer than the journal; content-equal renders are never re-journaled.
- Poisoned legacy JSON is decoded on read without side effects; the next normal write backs up and repairs it. Heuristic repair during reads is forbidden.
- Journal damage is tolerated with diagnostics; a journal with no usable records fails closed. Rotation archives old journals with rollback safety.
- Writes use `.agents/memory/MEMORY.md.lock` (cross-process ownership, stale-lock recovery, backups, atomic replacement). `errors.log` is append-only, rotated/redacted, and redacts credential-shaped strings.
- Memory rendering defaults to `MAX_MEMORY_CHARS = 32000`, configurable via `maxMemoryChars` (4000–200000). Truncation keeps whole lines and appends a strict marker; the limit is passed explicitly through normalization, folding, loading, comparison, and recording.
- `normalizeMemoryDocument` is idempotent; `exceedsMemoryCap` strips the marker before measuring, so a copied marker on a short reply is not a cap event. `memoryDocumentChars` counts an empty body as 0. `memorySizeLabel(chars, cap)` is the single label used by `status` and `/memory`.
- `MEMORY.md` prompt schema (`memory/schema.ts`): fixed 4 sections Project 20% / Invariants 40% / Pitfalls 25% / Index 15%; the consolidation prompt subtracts fixed overhead before budgeting. Long explanations are pointerized to versioned `docs/` paths that must already exist. This is a convergence target, not a storage gate.
- `CONTEXT.md` has a fixed 3-section schema (`memory/context-schema.ts`): `Summary` (prose, share 0.4, hard-capped by `MAX_SUMMARY_CHARS`), `Key points` (0.35), `Open tasks` (0.25); `contextSchemaOverheadChars()` = 349; prompt and renderer share `contextSectionBudgets(cap)`. Over-budget renders drop whole trailing items per section first, then append the strict last-line marker `_[context truncated: N characters dropped]_`; the dropped count uses the normalized-but-untrimmed full render. `contextTruncationDropped`/`isContextTruncated` accept the marker only on the final line; truncation is logged once per project per process by `memory/report.ts`. `MAX_LIST_ENTRIES` lives in `shared/limits.ts`.
- Known CONTEXT.md residuals: the marker reservation is pinned only by the `overhead === 349` constant; the `title` 160-char trim is metadata clipping and is not counted in the marker; tail scope is a fresh-render policy.
- Consolidation context must be an object with `summary` string, `title` string, and `key_points`/`open_tasks` arrays of strings. Missing or unusable context is logged and the previous `CONTEXT.md` is retained.
- Consolidation's primary failure mode is protocol/capacity mismatch: one JSON reply must carry the whole rewritten memory and context, and provider output limits plus dense CJK tokenization can truncate. Mitigations in place: one bounded retry with a stricter JSON-only instruction, and one bounded condensation call when the reply exceeds the character cap. Remaining durable fixes: truncation/finish-reason diagnostics, incremental/split updates.
- Structured consolidation output is **implemented** (2026-10-02): consolidation calls a strict-ready `record_memory` tool and code renders the `MemorySections`, so the schema never guarantees the cap. Safety gates: all four sections semantically empty means treat as unchanged and never write (a headings-only skeleton must never satisfy a rendered-length change check); the Markdown extractor accepts only an optional one-line `# Project Memory` header plus exactly the four known headings with bullet entries, and returns `undefined` on any prose/unknown/preamble content, which falls back to the opaque path; per-section clipping is surrogate-safe and drops whole items; the renderer writes no truncation marker. see `.codestable/issues/2026-10-01-structured-consolidation-output/structured-consolidation-output-design.md`, `implementation-note.md`.
- The opaque fallback normalizes the reply (code fences including ```json/```md info strings, `~~~`, leading separators, zero-width characters) before the semantic-emptiness check; the first-cut single-layer strip was bypassable end-to-end.
- Shared structured-output helpers: `callAux(ctx, prompt, {model, maxTokens, tools, scope, projectRoot, state})` owns `noteModelSuccess` and `noteModelFailure` (recorded once, only after both attempts); `scope`/`projectRoot` are the accounting identity. `pickToolCall(toolCalls, name, text)` takes the reply text because `completeWithMeta` is name-agnostic — a name-mismatched toolCall with non-empty text must fall back to text, one with empty text must error; the policy lives in exactly one place. The per-pass sticky no-tools switch lives in the caller-supplied `state`.
- Structured and fallback-sections reply paths bypass `normalizeMemoryReply`/`clipToLineBoundaryBothEnds`; the opaque path is unchanged and keeps `exceedsMemoryCap` plus the 60/40 marker. The condensation retry triggers on `sectionDropped > 0` for structured/parseable replies and on `exceedsMemoryCap` for the opaque path; retry and condense calls always send without `tools` and use the `{memory_markdown, context}` shape. No numeric `max-memory` suggestion is emitted on the structured/parseable paths.
- `tools`-rejection fallback (consolidation and autolearn): exactly one no-tools retry on the first tools call that throws in a pass, sticky for the rest of the pass, **gated on the failure not being provider-level** (design said unconditional; deviation D1, accepted — otherwise a provider outage doubles call volume and breaks `call-policy` backoff). `noteModelFailure` is counted once, only after both attempts fail. `constrainedSampling` is passed through unchanged; strict resolution/downgrade lives in the pi-ai adapter, not the extension.
- Auxiliary JSON consumers are exactly two: consolidation (`memory/pass.ts`) and autolearn (`autolearn/pass.ts`); handoff resolves the auxiliary model and threshold but parses no JSON. Autolearn's strict-ready schema must be always-object (sentinel empty name means no skill; no `null`, no object union) and must use `completeWithMeta`, because `completeText` drops `stopReason`.
- `makeStrictJsonSchema(schema, isUnsupportedKeyword?)`: the callback is optional in the installed source (`if (isUnsupportedKeyword)` guard) — do not restate it as required. Strict tool support defaults off (openai-completions, Bedrock, anthropic-messages) and on for Google; `anyOf:[<object>, {type:"null"}]` is rejected in strict mode.
- `maxLength`/`maxItems` never go in a schema: pi-ai's base forbidden table is 16 keys (`constrained-sampling.js:3-20`); the Anthropic adapter adds 11 more (`anthropic-messages.js:1223-1235`, includes `maxItems`; `format` whitelist `:1236-1247`; predicate `:1248-1256`; `minItems` only 0/1). `maxItems` on an Anthropic route silently downgrades under `prefer`. The cap is enforced by code only.
- `description` is strict-safe (verified): it is in neither table; a nested schema with `description` passes `makeStrictJsonSchema` and is preserved at every level including `items`.
- Tool descriptions follow pi's house style: the tool-level description is what it does, when to call, returns/side-effects, global constraints; field-level constraints live in each field's own `description`. Delivered built-in tool description lengths: `edit` 326, `read` 303, `bash` 248, `grep` 221, `find` 186, `ls` 184, `write` 127. Frozen: `record_memory` 413, `record_skill` 294.
- Archive state: `.agents/memory/session-logs/<session-id>/{session.jsonl,session.md}` plus a derived `INDEX.md`; the directory carries a local `.gitignore` (`*`) so transcripts are machine-local and untracked. `INDEX.md` is `# Session Index` plus newest-first `- [id](id/session.md) — date — title` lines, cap 200 with per-id dedupe and a dropped-count comment.
- The archive copies the harness session file (`ctx.sessionManager.getSessionFile()`); `archive/session-log.ts` appends incrementally: the cursor keys off the archive's own byte size, writes are serialized per project+session via a promise chain, short reads are truncated with `bytesRead` instead of NUL-padded, rebuilds never inject synthetic bytes, and a `Buffer.equals` probe compares the last 256 bytes of archive vs source before appending; a differing or unreadable probe forces a full rebuild.
- Accepted archive residuals: the 256-byte probe cannot see a same-inode rewrite that preserves those bytes and does not shrink; `bytesRead`, `if (tail)`, the probe `catch`, and the trim-empty cursor skip are unpinned; cross-process writers of the same session are unlocked; a UTF-8 mid-byte read can render U+FFFD until the next refresh rebuilds.
- The archive layer injects `CONTEXT.md` read-only; `CONTEXT.md` is produced by consolidation, so a failed consolidation leaves it stale.
- Session transcripts are stored raw: `redactSecrets` is applied only to `errors.log` (`shared/error-log.ts`), never to archived content.
- No code prunes session-log directories (only the `INDEX.md` list is capped at 200). Measured 2026-10-01: local `session-logs/` = 91MB / 48 sessions, largest 4.3MB.
- Project skills `.agents/skills/pi-project-context-session-log-archive-repair/SKILL.md` and `.agents/skills/pi-project-context-structured-tool-output-strict-mode/SKILL.md`.
- `shared/call-policy.ts` classifies auxiliary failures (`auth`, `quota`, `transient`, `shape`, `other`) and drives per-project, per-scope cooldown with exponential backoff; after 5 consecutive provider failures automatic passes are disabled for the session while explicit commands (e.g. `/autolearn`) still run. Exists because a provider outage previously caused a retry storm on every `agent_settled`.
- `shape` failures (JSON shape/truncation) must not trigger route cooldown; only provider-level failures do. Any attempted auxiliary call records success or failure.
- The consolidation prompt is told the real hard cap (`maxMemoryChars`) and the current character count, and must never write omission/truncation markers.
- An over-cap reply triggers exactly one bounded condensation call (keep durable facts, merge duplicates, drop the least durable); if it still overflows, the original reply is kept and the existing cap warning speaks. Silent tail-dropping is not acceptable.
- `memory/document.ts` owns the cap math. The suggested `/project-context max-memory <n>` is tight and clamped to `[4000, 200000]`.
- M7 upper-bound check: `memoryCapUnsatisfiable` / `memoryReplyTokens` warn when re-emitting a cap-sized memory would need more output tokens than `max(maxTokens, maxOutputTokens)`; `status` and the `max-memory` verb share one `capCeilingWarning` sentence.
- Handoff uses `ctx.newSession()` and stages settings in `handoff-session-settings.json`; successor startup restores the outgoing model and thinking level only for the matching predecessor, then consumes the staged file.
- Handoff language supports `auto`, `zh`, `en`; replay filters old handoff prompts, allows in-turn cut points, preserves valid roles, and excludes orphan tool results. Summary headings use pi's fixed set localized by `localizeSummaryHeadings`; `HANDOFF.md` adds the document header (Created/Project/Log/Index).
- Adaptive threshold: `knee(W) = W − (W − 157000) · sigmoid(ln(W / 450000) / 0.04)`; `tokens = max(min(usable − 4000, knee(W)), baseline + keep + handoffTargetTokens)` where `usable = W − 16384`, then capped in order by summarizer capacity, first pricing tier, and `usable − 4000`; below `baseline + keep + 8000` returns undefined. Large declared windows saturate at 157K.
- Rejected threshold alternatives (owner-corrected): target-driven formulas, the two-term window share, the half-window (49%) and window-end (98%) rules. The 273K/650K fit was replaced by the conservative 157K/450K fit; a flat `min(W, 157K)` plateau was rejected as too early.
- `Threshold.summarizeTokens = tokens − baseline − keep` drives the status line's projected summary input after caps; falls back to configured `target` when usage is unavailable. A status line without `· summarize …` means a stale process.
- Standing decision: caps may only lower a computed threshold, never raise it; the status line names the binding bound and must not overstate the summarize amount. A first-tier edge below `floor + 4000` makes auto return undefined.
- Pinned threshold test values: 1M → 157,000 (summarize 125,076); 400K → 379,616; 768K → 157,001; 272K → 251,616; usage 512K → 583,924 (bound `target`); 1M + 120K tier → 116,000 (bound `tier`); tier edge at `floor + 4000` → 39,924; below → undefined; 128K summarizer → 127,156; 64K window → 43,616.
- `/handoff auto` takes no ratio parameter; `handoffThresholdRatio` is fixed-mode only. `handoffTargetTokens` is the physical floor's summarize target before caps, reported by `/handoff target`.
- If `ctx.model` is missing while staging a handoff, only thinking settings are carried and an explicit diagnostic is written.
- Configuration is in `.agents/memory/project-context.json` or the project root. Keys: `autoConsolidate`, `autoLearn`, `archiveEnabled`, `handoffEnabled`, `maxTokens`, `maxOutputTokens`, `maxMemoryChars`, `consolidateTurns`/`consolidateIntervalMs`, `autolearnTurns`/`autolearnIntervalMs`, `handoffKeepTokens`, `handoffAdaptive`, `handoffThresholdRatio`, `handoffTargetTokens`, `handoffLanguage`.
- Auxiliary models honor configured provider/model and otherwise use the authorized session model; unresolved routes warn once per process. Empty `provider`/`model` means the session model is used.
- `session_shutdown` always performs a forced silent consolidation; `agent_settled` consolidation is conditional and fire-and-forget. `--no-project-context` disables project-context features for a run.
- Release procedure: commit, annotated tag, push tag and `master` to both remotes, bump the pin in the separate `pi-config` repository, verify installed tagged blobs, run a real settings-installed probe, record evidence, then commit release documentation separately (the evidence commit lands on `master` after the tag; the tag stays on the release commit).
- Memory render changes are committed as `docs(memory): refresh the memory render`, separate from code commits.
- Directory-shaped extensions are installed only through pi packages (`pi install <source>@<ref>`); never copy them into `~/.pi/agent/extensions` and never add a `package.json`.
- Threshold, cap and budget tests pin exact numeric values plus label/summarize strings. `git diff --check` kept clean.
- Command naming (2026-10-01, **implemented**): verbs-as-args; `/memory-learn` → `/memory update`; `/context-update` deleted with no alias and no transition period; `/context` unchanged (CONTEXT.md is a consolidation product, not a session log); `/auto-handoff` → `/handoff`; `/memory`, `/session-log`, `/project-context`, `/autolearn` unchanged. Every surviving command registers `getArgumentCompletions` (`RegisteredCommand`, `dist/core/extensions/types.d.ts:1132`). see `.codestable/issues/2026-10-01-command-naming-consolidation/command-naming-inventory.md`.
- pi completion: Tab autocompletes (`tui.input.tab`, `docs/keybindings.md:89`) and `/` opens the command search menu; extensions may register `getArgumentCompletions(argumentPrefix) → AutocompleteItem[]`.
- Tests use `rmTemp()` (`fs.rm` with `maxRetries`) for temp cleanup, never bare `rm -r`: the extension's fire-and-forget background write races teardown and intermittently raises `ENOTEMPTY`. 48 call sites converted.
- Session-archive durability is deferred (owner, 2026-10-01): stay local-only; investigate comparable projects before deciding. ## Pitfalls
- Consolidation fails closed on unparseable model replies; missing/unusable context is logged and the previous `CONTEXT.md` is retained.
- Over-budget memory replies are never silently tail-dropped: one condensation call, then the original plus a cap warning.
- `exceedsMemoryCap` strips the truncation marker before measuring; a copied marker on a short reply is not a cap event.
- A change guard keyed on rendered length (e.g. `>= 40`) is satisfied by a headings-only skeleton and would wipe `MEMORY.md`. Gate on semantic emptiness, not rendered length.
- Stripping the opaque fallback reply with a single layer is bypassable: ```json / ```md info strings, `~~~` fences, leading separators and zero-width characters all reached the skeleton check. Normalize first; the narrow first fix failed end-to-end review twice (one blocking each round).
- An independent-review round that returns empty output with an unchanged sandbox diff is a provider failure, not a PASSED review. Rerun it and never file it as a round — an `ENOTEMPTY`-style clean shell is not evidence.
- A model the current session is running on is not necessarily resolvable by a spawned `pi -p` process; verify with a one-line probe before starting a review round, not after 20 minutes of silence.
- Strict JSON-schema mode rejects `anyOf` with an object member; making the property non-required does not help — it gets wrapped into the same union and forced into `required`. Use an always-object shape with sentinel values.
- `makeStrictJsonSchema` nuance (probe-verified): a required `anyOf:[{object},{null}]` throws locally; an optional `type:"object"` property does not throw locally but is wrapped into that union and forced into `required`, silently violating the strict subset. `isStructuredSchema` (`constrained-sampling.js:24-30`) treats object/array/`properties` as structured. No object-union shape is acceptable. Passing `() => false` as the second argument disables the provider-side check entirely — it only pins base-table behavior and must not stand in for a strict-ready assertion.
- `completeText` discards `stopReason`; truncation or finish-reason discipline needs `completeWithMeta`.
- A measured claim can come from a broken probe in two ways seen here: (a) wrong probe precondition — the `makeStrictJsonSchema` second-argument-required claim came from passing the string `require` where a callback was expected; (b) wrong artifact measured — the built-in-tool-descriptions-are-222-to-344-chars claim came from measuring unexpanded `${…}` template literals inside `dist/core/tools/*.js`, not the delivered strings (real 127–326, longest `edit` 326). Before writing 已实测, state which artifact the number came from.
- A draft claimed `skill.reason` is not read back by code — false: `autolearn/parse.ts:28` reads it and `skill.ts:51` writes it into the candidate SKILL.md header.
- Heuristic repair of poisoned legacy JSON during reads is forbidden — decode without side effects, repair on the next normal write with a backup.
- Journal damage is tolerated with diagnostics, but a journal with no usable records fails closed; rotation must stay rollback-safe.
- `shape` failures must not trigger route cooldown; only provider-level failures do.
- Do not enable automatic passes on repeated provider failures; explicit commands still run while automatic passes back off after 5 consecutive failures.
- A tools-rejection retry must not fire on provider-level failures, or a single outage doubles auxiliary call volume.
- Test teardown with bare `rm -r` races the extension's fire-and-forget background write and intermittently raises `ENOTEMPTY`; use `rmTemp()` (`fs.rm` with `maxRetries`) at every cleanup site.
- The session archive's 256-byte probe cannot detect a same-inode rewrite that preserves those bytes and does not shrink; `bytesRead`, `if (tail)`, the probe `catch`, and the trim-empty cursor skip remain unpinned.
- Cross-process writers of the same session file are not locked; a UTF-8 mid-byte read can render U+FFFD until the next refresh rebuilds.
- Session transcripts are archived raw (`redactSecrets` only on `errors.log`); do not assume redaction of archive content.
- The `INDEX.md` list cap (200) does not prune session-log directories; local `session-logs/` was 91MB / 48 sessions on 2026-10-01.
- A failed consolidation leaves the archive-injected `CONTEXT.md` stale.
- A status line without `· summarize …` means a stale process; after `pi update --extensions` a relaunch is required.
- Caps may only lower a computed handoff threshold, never raise it; a first-tier edge below `floor + 4000` makes auto return undefined.
- Paid-route failures (deepseek 402, openai-codex invalidated token, commandcode plan-gated, scnet 429) must never be reported as successful validation.
- The extension's only git call is read-only (`shared/paths.ts:28`); auto-committing/pushing transcripts from the settle path is rejected as a default.
- Regex-only redaction cannot guarantee a secret-free archive; git history is irreversible, so never push regex-redacted transcripts to a shared/GitHub mirror.
- Do not assume dropping `toolResult` is harmless: live consolidation uses in-memory `ctx.sessionManager.getBranch()`, but autolearn reads the archive (`autolearn/evidence.ts:78-88`).
- A handoff summary can be staler than the worktree: verify `status:` lines, round counts and verdicts with tools before resuming, or completed rounds get re-run.
- A whole-document grep that reports a round verdict can match a `post-PASSED` phrase inside the row text instead of the verdict column; re-grep with a column-anchored pattern before trusting it.
