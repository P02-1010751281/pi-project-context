# Project Memory

## Project
- **pi-project-context** is a pi coding-agent extension suite providing durable project memory and session context: consolidation of `MEMORY.md`/`CONTEXT.md`, session archiving, autolearn, handoff summaries.
- Stack: TypeScript/ESM for pi extensions (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`), Node.js `fs/promises`, plain `node` test harness (`.mjs`) run via `tests/run-all.mjs`.
- Layout:
  - `extensions/project-context/`: `index.ts` (registration), `consolidate.ts` (memory/context pass), `project-state.ts` (storage, `loadMemory`, `memory.jsonl` journal fold/write, `recordMemoryDocument`, `memoryComparisonKey`, backup/write paths, lock, `logError`, `notify`, `MAX_CONTEXT_CHARS = 32000`, `MAX_SUMMARY_CHARS = 6000`, `MAX_LIST_ITEM_CHARS = 800`), `llm.ts` (JSON parsing, aux model resolution), `config.ts` (`project-context.json` defaults), `autolearn.ts`, `handoff.ts`, `archive.ts`, `session-log.ts`, `session-index.ts`, `import-archive.ts`, `context-doc.ts`.
  - `tests/`: harness (`harness.mjs` exposes `loadNamespace`, `loadDefault` (alias-override), `PC`, `waitUntil(predicate, timeoutMs, stepMs)` with async-predicate support, `makeSessionManager.appendMessage`, `contentEntry`/`toolResultEntry`, `makePi`), per-module `.mjs` tests, `run-all.mjs` aggregator (sequential `spawnSync`, 60s per-file timeout; currently 9 test files), `tests/helpers/lock-holder.mjs` (cross-process lock probe), `tests/cpu-hog.mjs` (pre-existing load generator). `tests/handoff-test.mjs` holds the handoff assertions; `tests/autolearn-test.mjs` holds sections H and I.
  - Rendered state lives in each project at `.agents/memory/` (`MEMORY.md`, `memory.jsonl`, `memory-log-*.jsonl`, `CONTEXT.md`, `HANDOFF.md`, `errors.log`, `session-logs/`, `project-context.json`, `skill-candidates/`, `handoff-session-settings.json`, backups/locks).
- `README.md` documents the suite; `.codestable/` holds issue reports, analyses, approval reports, fix notes, review reports; issues live under `.codestable/issues/<date>-<slug>/` with `…-report.md`, `…-analysis.md`, `…-fix-note.md`, `…-review.md`, `…-review-round<N>-independent.txt`, evidence files. Frontmatter fields used in issue docs: `doc_type`, `issue`, `status`, `path`, `created_at`, `related`, `tags`.
- A sibling **codex-project-context** port exists under `.codestable/features/2026-09-15-codex-project-context-port/` (owned by a parallel Codex app-server session); pi-project-context is its behavioral baseline. The directory is intentionally untracked by git — keep it when cleaning the tree. `.agents/` is likewise intentionally untracked.
- Sibling repos used for real-world validation: `../UniField`, `../Quantum_Matrix` (each has its own `.agents/memory/`; in both, `MEMORY.md` and `CONTEXT.md` **are git-tracked**, so hand rewrites show up as working-tree modifications and follow the owner's commit rules).

## Conventions & standing decisions
- **Memory is journal-backed** (same architecture as session archive): `.agents/memory/memory.jsonl` is the append-only source of truth (`replace`/`append` records, one `write` per record, one line per record); `MEMORY.md` is its derived render (human-readable, injection text, external-edit entry point). Never write raw JSON envelopes or credentials into the journal, and never store generic advice in memory.
- Reading memory folds the journal in order; if no journal exists, the legacy read path is used (including poison decode), so old projects need no migration — the first write adopts the current `MEMORY.md` as the journal baseline.
- Consolidation must fail closed: never write an unparseable model reply as memory. Prefer failing the pass over corrupting memory.
- Parse model JSON via `llm.ts::parseJsonObject`; `project-state.ts::readJsonStringField` is the shared decoder for known field names (tolerates unterminated strings; maps `\b`/`\f` escapes).
- `loadMemory()` is the single shared read path for injection, consolidation, and autolearn; returns `{ text, source, poisoned, unreadable, damaged, ... }` and distinguishes ENOENT from unreadable (unreadable is logged and surfaced by `/memory`, not shown as "no memory"). With a journal present, `source` is the journal path, not `MEMORY.md`.
- Standing decision (owner-approved): `memory-heal-mode = B` — poisoned stored replies are decoded on read with no write side effect; the on-disk poison is repaired by the next normal consolidation write, which takes a `.poison-backup-*` of the raw file first. Heuristic repair as a write inside the read path is forbidden.
- Poison decode accepts `memory_markdown` as the first key, an empty/`[`/fence/`json`/single-short-preamble-line prefix, header-less document values, and legacy `.pi`/OMP sources; it rejects nested examples and short values so real memory is never replaced by example content. The decoder is internal (not exported); validate decode behavior by copying raw bytes into a temp `.agents/memory/MEMORY.md` and calling `loadMemory` there.
- **External-edit rule (single point of truth: `recordMemoryDocument` / `loadMemory` both use `memoryComparisonKey`)**: a render counts as an external edit only when its normalized content differs from the folded journal **and** its mtime is newer than the journal's. Content-equal renders are never adopted (even with newer mtime), so the extension's own renders are not re-journaled. External edits are honored for injection and folded into the journal as a `replace` record on the next write, with an `errors.log` note. A read-only session (no new-code write yet) can therefore leave `fold != render` — expected, not damage.
- Journal damage tolerance: torn tail is terminated (leading newline added) before the next append; damaged lines are skipped and counted in `LoadedMemory.damaged` (reported to `errors.log` and `/memory`). A journal with zero usable records fails closed — `/memory` tells the user to delete `memory.jsonl` to rebuild from `MEMORY.md` or restore from `memory-log-*.jsonl`.
- Journal rotation: at >512KB it folds to a single `replace` inside the lock, archives the old bytes as `memory-log-<stamp>-<8hex>.jsonl` (5 retained, files younger than 1 hour protected), and uses "temp file → archive → replace with rollback" so the `memory.jsonl` path never disappears. The rotation temp is named `memory.jsonl.<epoch-ms>.<uuid>.tmp` so it matches both the memory gitignore and `cleanStaleTemps`.
- `backupMemoryBeforeWrite()` runs before every `MEMORY.md` overwrite: reads current on-disk bytes, names backups `MEMORY.md.memory-backup-<stamp>-<rand>`, fails closed when the target exists but cannot be read (`ENOENT` is the only "no file" case), and prunes by mtime keeping 5, but backups younger than one hour are never pruned and the newest-named backup survives a burst; total backups are hard-capped at 20. Prune skips any candidate whose `stat` fails rather than treating it as old.
- All `MEMORY.md` writes run under a cross-process lock `MEMORY.md.lock`: a unique token owns the lock, release and stale-steal both require a single-winner claim via `<lock>.steal`, existing lock/claim paths are classified with `lstat` so any non-regular entry (directory, FIFO, symlink, dangling symlink) is renamed aside (`.broken-<8hex>`) and self-heals, unreadable locks count as fresh, destructive steps re-verify inode/bytes/claim ownership before removing, and the whole retry path respects the deadline with backoff.
- Residual accepted risk (documented in `stealStaleLock` comments): the final check→unlink step cannot be made kernel-atomic with `node:fs` (no `flock`); exposure is a transient mutex loss if a process is suspended >30s inside that window — atomic rename plus pre-write backups mean no file corruption.
- Residual accepted risk (journal): an external hand edit landing in the same mtime tick as a journal append is overwritten by the journal (mtime granularity); a concurrent append during rotation stays in the archived `memory-log-*.jsonl` (evidence preserved, not in the folded view) and is recomputed by the next consolidation.
- `cleanStaleTemps` reclaims old `*.tmp` (matching `\.\d+(?:\.[0-9a-f-]{36})?\.tmp$`) and `.broken-*` artifacts, but only deletes a broken artifact when it is an empty, over-age directory — anything with content is left as possible user data. `errors.log` itself is never rotated by the extension (append-only, unbounded).
- `errors.log` redacts credential-shaped strings (`sk-`, `ghp_`, AKIA, JWT, Bearer, key=value) before writing; consolidation failures log the raw reply head (≤4000 chars) there while UI notifications show only the first line.
- Consolidation output budget is adaptive: `replyTokenRate()` charges every non-ASCII code point and JSON escape sequence; `fitMemoryInput()` raises the output cap to `max(config.maxTokens, needed)` bounded by `config.maxOutputTokens` (default ceiling 32768); `allocateTokens` gives each artifact a floor then distributes the rest by need; `clipText` iterates on real text, keeps the character-count bound, and compensates head/tail boundaries so surrogate pairs are never split. When still insufficient the memory prompt is clipped to head 60% / tail 40% with a `clipped` flag, a backup, a user warning, and an `errors.log` trace; remaining budget flows back to the context slot.
- Auxiliary model calls go through `llm.ts::resolveAuxModel` honoring `provider`/`model` config, falling back to the session model when it resolves and is authorized; unresolved routes warn once per process.
- Config keys live in `.agents/memory/project-context.json` (or project root) with defaults in `config.ts`; documented keys include consolidation cadence, `maxTokens`, `maxOutputTokens`, `autoConsolidate`, `autoLearn`, `handoffKeepTokens` (default 20000), and `handoffLanguage` (`auto`|`zh`|`en`, default `auto`; nested `handoff.language` and the legacy global file are read for compatibility). Autolearn gates: `autoLearn`, then `changed` (max mtime of `MEMORY.md`/`CONTEXT.md` > `autolearnAt`) and `due` (`totalTurns >= autolearnTurns` (20) or `now - autolearnAt >= autolearnIntervalMs` (30 min)), then a non-empty archived set (directories under `session-logs/` containing `session.jsonl`). `autolearnAt: 0` is the default and means "always changed/due". `--no-project-context` disables all features for a run.
- Consolidation input is the **calling process's own live session** (`consolidate.ts` reads `ctx.sessionManager.buildContextEntries()`), so no external/probe process can materialize another session's content into memory; the designed path for hand-authored updates is the external-edit route on `MEMORY.md`.
- Consolidation trigger points: `agent_settled` runs the pass only when `autoConsolidate` is true (`memoryEnabled`); `session_shutdown` always runs a forced silent pass (`consolidate(ctx, true, true)`) — this is by design and explains extra `MEMORY.md` + backup writes when a session is replaced (e.g. after handoff).
- `agent_settled` passes are fire-and-forget: they return before the model call completes (measured +4–14ms after `runHandlers` returns), so tests must poll for the call rather than assume it happened synchronously. Accepted consequence: under 32-hog load with a broken gate mutation, a `/tmp/pi-autolearn-empty-*` dir (INDEX.md only) can be left behind; pure /tmp hygiene, same pre-existing fire-and-forget pattern as the H/archive sections.
- **Handoff language follows the conversation**: `handoffLanguage: auto` resolves via three rules — (1) user-side messages with ≥2 CJK chars → `zh`; (2) ≥20 Latin letters (substantive English) → `en`; (3) otherwise carry forward the language of the most recent handoff prompt. Sampling excludes handoff prompts and the omission marker and prefers the most recent ~8 messages.
- `/auto-handoff lang auto|zh|en` sets the language mode; `status` renders it as e.g. `lang auto (zh)`. Prompt scaffolding, `HANDOFF.md` document headers, and the `over threshold` placeholder are localized; the summary model call appends a language directive.
- The summary model's language obedience is not reliable (it copied pi's English template headings), so `handoff.ts::localizeSummaryHeadings()` deterministically maps summary headings zh↔en (line-exact matching; inline references and fenced code blocks are left untouched). Test samples come from a real-run English-heading summary.
- **Old handoff prompts inside the replay slice are replaced by a one-line `[handoff prompt omitted]` marker** (`REPLAY_MARKER`), not deleted: deleting would make the replay block open with `assistant(toolCall)`, which Anthropic/Gemini routes reject (400). The slice start still comes from `findCutPoint`, so pi's turn alignment is preserved.
- **In-turn cut points are used directly**: the cut no longer backtracks to the turn start, so a single oversized turn no longer blocks handoff. The kept slice is the in-turn cut; the dropped prefix goes into the summary input. If the replay block would open with a non-user role, a user-role `SPLIT_TURN_MARKER` (`[turn prefix summarized during handoff]`) is prepended; `USER_FACING_ROLES = {user, custom, bashExecution}` (the latter two map to the user role after session conversion). Intended semantic change: the keep budget is now an honest truncation bound rather than a whole-turn upper bound (reverse by reverting `093dbf3` or setting `handoffKeepTokens: 0`).
- **Orphan tool results are dropped from the replay by `toolCallId` matching and folded into the summary input** (`replayMessagesFor(entries, droppedOrphans?)` returns the dropped ones; `runHandoff` appends them to the summary input). This happens when a cut lands on a `branch_summary`/`compaction` entry and separates a `toolResult` from an already-prefixed `toolCall`; orphans are structurally illegal in a replay (provider 400). Lossy by design: content survives only through the model summary.
- Handoff accounting: `olderTokens` counts the dropped **prefix only** (orphans stay in the raw kept slice and are therefore counted in `sliceTokens`), so `baselineNow = usage − olderTokens − sliceTokens` never double-decrements. Token estimation uses the host's `estimateTokens`.
- Handoff switches sessions in-process via `ctx.newSession()`, so a code/version change only takes effect for processes started after the switch; the process that starts a handoff keeps running the code it loaded at startup.
- Self-skipping auto handoffs are not silent: the empty-session and nothing-older paths `notify(…, "warning")` and, when auto-triggered, record a ~30s cooldown so the skip is not re-reported on every `agent_settled`.
- **Handoff carries the session model/thinking across the session switch**: `ctx.newSession()` accepts only `{parentSession, setup, withSession}` and has no model option (`dist/core/agent-session-runtime.js:147` resolves model/thinking from config defaults); `setup(sessionManager)` runs after the runtime exists and only rebuilds messages (`agent.state.messages = buildSessionContext().messages`), so entries appended there do not change the live session, and the new runtime's `session_start` is emitted before `setup`. Therefore `handoff.ts` stages `{previousSessionFile, model, thinkingLevel, at}` atomically into `.agents/memory/handoff-session-settings.json` (auto-added to `.agents/memory/.gitignore`; TTL 10 min) before the switch, and a fresh extension instance's `session_start` handler (`reason === "new"` + predecessor match + TTL) consumes the marker and applies `pi.setModel()` → `pi.setThinkingLevel()`, skipping when the replacement session already matches. `/new`, `resume`, and `fork` never inherit settings (pi-native semantics kept); cancel/throw clears staging; every failure path is fail-open with a warning or `errors.log` entry. The old `pi` and old command `ctx` are stale after replacement (`ReplacedSessionContext`/`ExtensionCommandContext` only add `sendMessage`/`sendUserMessage`, no model/thinking setters), so the fresh `session_start` handler is the only usable point.
- **Handoff session tree is root-flattened**: `parentSession` is set to the oldest ancestor found by following the `parentSession` header (first line of each ancestor file, read ≤64KB, hop cap 32, cycle-guarded), not the immediately previous session. Depth stays at 2 while the workstream grouping under the origin root is preserved, and the newest handoff sorts directly under the root (session selector sorts children by subtree latest activity desc; each handoff chain rendered as always-expanded 3-char-per-level indentation, so a chained tree buries the newest session at the bottom). Alternatives kept on the table: depth-capped chaining (≤4 levels), no parent at all (B2), or the previous chained behaviour (B3, rejected).
- pi's session selector builds its tree from each session file's `parentSessionPath` (`dist/modes/interactive/components/session-selector.js:164`); its threaded default is permanently expanded, indentation is 3 chars per level (`buildTreePrefix`), and no selector action uses the parent link (no jump-to-parent, no lineage-aware delete), so nesting is purely visual. Sort mode toggles `threaded → recent → relevance` (`:828`), the latter two being flat lists; children/roots sort by subtree latest activity descending. pi's own `examples/extensions/handoff.ts` chains `parentSession` to the current session, which deepens the tree by one level per handoff.
- Reviewer-round convention: each independent round gets its own transcript `…-review-round<N>-independent.txt` and a row in the issue's `…-review.md`; fix rounds are recorded per round in `fix-note §6`. Blocking findings must be fixed or explicitly accepted by the owner before a fix is declared complete; the owner decides whether to run another round after a no-blocking round. Fix-note frontmatter goes `draft` → `confirmed` once all blocking/important findings are closed.
- Code review gates: lane A needs an independent reviewer — a non-interactive `pi` CLI process (`pi -p --no-session --no-extensions --no-skills --no-prompt-templates --tools read,bash`) on a read-only sandbox copy (copy repo to `/tmp`, snapshot `git status` + file stats before and after to prove zero writes) qualifies; record the transcript path as the run ref. Lane B needs the `ocr` CLI. When lane A is unavailable the gate stops at an owner decision, and `reviewer: self` passes the runner gate only with `CODESTABLE_ALLOW_SELF_REVIEW_FALLBACK=1`.
- Long reviewer runs should be backgrounded (`nohup … &` plus polling) so a tool-call abort or provider failure does not kill the review; an interrupted run leaves a 0-byte transcript that must not be recorded as evidence.
- Headless end-to-end validation of handoff works via `pi --mode rpc -ns --thinking off -e <repo>/extensions/project-context/index.ts --provider … --model … --session-dir <dir>` against a scratch project with `handoffKeepTokens` set low; send `/auto-handoff now` twice to exercise chained handoffs. The TUI-only auto-trigger path (`maybeTrigger`, `ctx.mode === "tui"`) is exercised in real use; the RPC path cannot exercise it. Detecting which build a running process uses: grep the live session file under `~/.pi/agent/sessions/…` for `[turn prefix summarized during handoff]` (v0.1.5+) and `[handoff prompt omitted]` (v0.1.4+).
- **Probe hygiene: `-ne` is `--no-extensions` and disables settings-installed packages entirely** — only explicit `-e <path>` extensions load. To verify that an installed package is live, omit `-ne` (keep `-ns` if needed) and observe a version-specific side effect. In `pi`'s TUI a `/command` needs autocomplete acceptance plus a second Enter before it executes; typing text into the editor with LF instead of CR does not submit (pexpect `sendline` sends LF — use `send(text + "\r")`).
- Test-race convention: no fixed sleeps for concurrency windows — use `harness.waitUntil` (async-predicate capable), deterministic nesting (the lock holder starts followers/contenders inside its own critical section and yields 3×(`setImmediate` + `setTimeout(0))`), and bounded negative probes (`stayedQuiet`, `quietAfterSettle`). Only true deadline semantics (e.g. lock-deadline tests asserting an upper bound) keep real waits. Honest limit: an in-process window cannot defeat arbitrarily delayed bypasses; the cross-process lock probe (`tests/helpers/lock-holder.mjs`) is the authoritative mutex check.
- Mutation-testing convention for negative probes: a probe must fail when the gate it claims to cover is mutated, and must not turn red when other gates are mutated. A probe whose gate is absorbed by an earlier guard has no detection power (m3 — the autolearn switch absorbed by archived-count/off state in `tests/switches-test.mjs` — and m4 — `archived.size === 0` uncovered — were found this way; m3 is fixed and review-confirmed; m4 is recorded open). The handoff session-continuity probes now use a 9-gate mutation matrix with one-to-one orthogonality (m1→5 red, m2→2, m3→1, m4→2, m5→3, m6→1, m7→1, m8→1, m9→1).
- Autolearn probe layout: `tests/switches-test.mjs` builds a fixture whose only false gate is the autolearn switch (materials + archive present) with a prompt-distinguishing `learnCalls` counter and cumulative `stayedQuiet(() => learnCalls > 0)`; `tests/autolearn-test.mjs` section I uses its own tmp project with `{autoLearn: true, autolearnAt: 0}`, no archived session, a **second** pi instance (because `pi.exec` resolves the project root from the pi's own cwd, and single-flight/throttle state must not be shared with the main instance), a negative probe (no model call within 500ms, a shared counter reset before the positive control) and a positive control (add one archived `session-logs/<id>/session.jsonl` → the model must be called). Mutation matrix: archived gate → section I red only; switch → all green (its project has the switch true); changed/due → only section H red. Probe sensitivity boundary: a mutated pass whose model call is delayed >500ms can escape the negative probe (measured real latency 5–20ms, so 25–100× margin); tightest fix needs an exposed pass-completion signal, judged not worth the cost.
- Handoff test-callpoint pinning: the harness supports alias overrides, so a tmp-generated module can `export * from "<pi>/dist/index.js"` plus explicitly re-export `generateSummaryWithUsage` delegating to `globalThis.__handoffStub` (explicit exports win over `export *`), combined with a `newSession` mock on ctx; this pins the summary input, language directive, heading localization, replay slice shape, and the `HANDOFF.md` content.
- Real-machine validation pattern: run the extension against a scratch project via `-e` on the local path (leaves the installed version untouched), then verify journal/render/session artifacts and assert `foldMemoryJournal(entries) === MEMORY.md` and `loadMemory(root).source === memoryJournalFile(root)`.
- pi package management: specs are managed by `pi install` / `pi remove` / `pi list`, `pi update --extensions` updates packages and reconciles pinned git refs only (no CLI update), `pi update --self` updates pi. Pinned git refs are checked out in `~/.pi/agent/git/<host>/<owner>/<repo>` and fetched as `tag <ref> -> FETCH_HEAD`, so the installed clone may have no local tag objects (`git describe --tags` can look behind); confirm the checked-out commit hash instead of tags.
- Auth for real-model probes lives in `~/.pi/agent/auth.json`; deepseek/opencode entries are `{type: "api_key", key}` and openai-codex is OAuth. Probe scripts keep credentials out of the repo (ad-hoc scripts under `/tmp`) and record transcripts as issue evidence. A provider balance failure (deepseek HTTP 402) aborts a probe with no output; check balance and re-run rather than recording the empty transcript.
- Workflow: investigate via `cs-issue`/`cs` docs, keep `.codestable` artifacts current (report → analysis → approval report → fix note → review report), and confirm plans at checkpoints before writing code.
