# Project Memory

## Project
- **pi-project-context** is a TypeScript/ESM pi coding-agent extension suite providing durable project memory, session context, archiving, autolearn, and handoff summaries.
- Stack: Node.js, `fs/promises`, `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`; tests are plain `.mjs` files run by `tests/run-all.mjs` (12 suites).
- Main code is under `extensions/project-context/` with a split module layout: `memory/`, `autolearn/`, `handoff/` (facade `handoff.ts` re-exports) and `shared/` (config, llm, call-policy, project-state facade, paths, limits, files, notify, redact, lock, gitignore, error-log, migrate, text, output-budget, conversation).
- Rendered state lives under each project's `.agents/memory/`. `.codestable/` stores issue reports, reviews, fix notes, release evidence; preserve `.codestable/features/2026-09-15-codex-project-context-port/`, the issue records `.codestable/issues/2026-09-30-auxiliary-call-noise-and-memory-cap/` and `.codestable/issues/2026-09-30-session-log-append-duplication/`.

## Durable memory and context
- `.agents/memory/memory.jsonl` is the append-only source of truth; `MEMORY.md` is the derived render and external-edit entry point. Records are `replace` or `append`.
- `loadMemory()` is the shared read path and distinguishes missing, unreadable, damaged, poisoned, and journal-backed memory. Consolidation fails closed on unparseable model replies.
- External `MEMORY.md` edits are adopted only when normalized content differs from the folded journal and the render is newer than the journal; content-equal renders are never re-journaled.
- Poisoned legacy JSON is decoded on read without side effects; the next normal write backs up and repairs it. Heuristic repair during reads is forbidden.
- Journal damage is tolerated with diagnostics; a journal with no usable records fails closed. Rotation archives old journals while preserving rollback safety.
- Writes use `.agents/memory/MEMORY.md.lock` with cross-process ownership, stale-lock recovery, backups, and atomic replacement. `errors.log` is append-only, rotated/redacted by `shared/error-log.ts`, and redacts credential-shaped strings.
- Memory rendering defaults to `MAX_MEMORY_CHARS = 32000`, configurable via `maxMemoryChars` (4000–200000). Truncation keeps whole lines and appends a strict marker; the limit is passed explicitly through normalization, folding, loading, comparison, and recording.
- `normalizeMemoryDocument` is idempotent: an already-clipped render is not re-clipped, and its marker is re-appended only in the exact marker shape (`exceedsMemoryCap` strips the marker before measuring, so a copied marker on a short reply is not a cap event).
- Consolidation context must be an object with `summary` string, `title` string, and `key_points`/`open_tasks` arrays of strings. Missing or unusable context is logged and the previous `CONTEXT.md` is retained.
- Consolidation's primary failure mode is protocol/capacity mismatch: one JSON response must carry the whole rewritten memory and context, and provider output limits plus dense CJK tokenization can truncate before closing quotes/braces or yield schema-invalid output. Mitigations in place: one bounded retry with a stricter JSON-only instruction, and a single bounded condensation call when the reply exceeds the character cap. Remaining durable fixes: truncation/finish-reason diagnostics, structured output, incremental/split updates.

## Session archive
- Archival state lives at `.agents/memory/session-logs/<session-id>/{session.jsonl,session.md}` plus a derived `INDEX.md`; the directory carries a local `.gitignore` so transcripts are machine-local and untracked.
- `archive/session-log.ts` copies the harness session file incrementally: the append cursor keys off the **archive's own byte size** (not a pre-read `stat`), writes are serialized per project+session via a promise chain (so `/session-log` and turn/settle paths cannot interleave), short reads are truncated with `bytesRead` instead of NUL-padded, rebuilds never inject synthetic bytes, and before appending a `Buffer.equals` probe compares the last 256 bytes of archive vs source; a differing or unreadable probe forces a full rebuild.
- Known and accepted residuals for the session archive: the 256-byte probe window cannot see a same-inode rewrite that preserves those bytes and does not shrink (no characterization test pins the blind spot); `bytesRead`, `if (tail)`, the probe `catch`, and the trim-empty cursor skip are unpinned defensive branches; cross-process writers of the same session are unlocked; a UTF-8 mid-byte read can render U+FFFD until the next refresh rebuilds.
- The archive layer injects `CONTEXT.md` read-only; `CONTEXT.md` itself is produced by the consolidation pass, so a failed consolidation leaves it stale until a later pass.

## Auxiliary model call policy
- `shared/call-policy.ts` classifies auxiliary failures (`auth`, `quota`, `transient`, `shape`, `other`) and drives per-project, per-scope cooldown with exponential backoff; after 5 consecutive provider failures the automatic pass is disabled for the session while explicit commands (e.g. `/autolearn`) still run.
- `shape` failures (JSON shape/truncation) must **not** trigger route cooldown; only provider-level failures do. Any auxiliary call that is attempted records success or failure through the policy.
- This exists because a provider outage previously caused a retry storm on every `agent_settled`; automatic passes now back off, and toasts name the failure class (quota/auth → switch route, transient → backing off).

## Memory character budget
- The consolidation prompt is told the real hard cap (`maxMemoryChars`) and the current character count, and must never write omission/truncation markers; the old ineffective "below 6000 words" wording was replaced.
- An over-cap reply triggers exactly one bounded condensation call (keep durable facts, merge duplicates, drop the least durable); if it still overflows, the original reply is kept and the existing cap warning speaks. Silent tail-dropping is not acceptable behaviour.
- `memory/document.ts` owns the cap math: `memoryDocumentChars` measures header + body (an empty body counts as 0, so a fresh project reports "empty"); `exceedsMemoryCap` measures the body only, so a marker copied from an older render cannot fake a "hit the cap" warning; `normalizeMemoryDocument` clips on whole lines (head + tail) and appends the strict marker, and the marker is excluded from the cap measurement. `memorySizeLabel(chars, cap)` is the single "empty" / "N chars, X% of the cap" label used by `status` and `/memory`.
- The suggested `/project-context max-memory <n>` is tight (setting the cap to the measured size drops nothing) and clamped to `[MIN_MEMORY_CHARS, MAX_MEMORY_CHARS_LIMIT]` (4000–200000).
- M7 upper-bound check: `memoryCapUnsatisfiable` / `memoryReplyTokens` warn when re-emitting a cap-sized memory would need more output tokens than `max(maxTokens, maxOutputTokens)`; `status` and the `max-memory` verb share one `capCeilingWarning` sentence.

## Handoff
- Handoff uses `ctx.newSession()` and stages settings in `handoff-session-settings.json`; successor startup restores the outgoing model and thinking level only for the matching predecessor, then consumes the staged file.
- Handoff language supports `auto`, `zh`, `en`; replay filters old handoff prompts, allows in-turn cut points, preserves valid roles, and excludes orphan tool results.
- Adaptive threshold: `knee(W) = W − (W − 157000) · sigmoid(ln(W / 450000) / 0.04)`; `tokens = max(min(usable − 4000, knee(W)), baseline + keep + handoffTargetTokens)` where `usable = W − 16384`, then capped in order by summarizer capacity, first pricing tier, and `usable − 4000`; below `baseline + keep + 8000` returns undefined. Honest windows ≤ ~400K sit on their own boundary; large declared windows saturate at 157K (population median of measured knees; 500K+/1M declarations are inflated). Deliberately conservative: strong 1M models trigger earlier than their own knee.
- Rejected alternatives (owner-corrected): target-driven formulas, the two-term window share, the half-window (49%) and window-end (98%) rules — all overshoot the measured quality knee (GPT-5.5 MRCRv2 8-needle degrades past 256K). The 273K/650K fit was replaced by the conservative 157K/450K fit; a flat `min(W, 157K)` plateau was rejected as too early.
- `Threshold.summarizeTokens = tokens − baseline − keep` drives the status line's projected summary input after caps; falls back to configured `target` when usage is unavailable. Examples: `auto 157k (16%) · summarize 125k`; Codex 272K `auto 252k (93%)`; usable-capped `auto 43.6k (68%) · capped by the usable window · summarize 23.6k`. A status line without `· summarize …` means a stale process.
- Standing decision: caps may only lower a computed threshold, never raise it; the status line names the binding bound and must not overstate the summarize amount. A first-tier edge below `floor + 4000` makes auto return undefined instead of silently crossing the paid boundary.
- Pinned test values: 1M → 157,000 (`auto 157k (16%)`, summarize 125,076); 400K → 379,616; 768K → 157,001; 272K → 251,616; usage 512K → 583,924 (bound `target`); 1M + 120K tier → 116,000 (bound `tier`); tier edge at `floor + 4000` → 39,924; below that → undefined; 128K summarizer → 127,156; 64K window → 43,616 (usable cap).
- `/auto-handoff auto` takes no ratio parameter; `handoffThresholdRatio` is fixed-mode only (`handoffAdaptive: false`, `/auto-handoff 0.6`) and auto must not silently accept it. `handoffTargetTokens` is the physical floor's summarize target before caps and is reported as such by `/auto-handoff target`.
- If `ctx.model` is missing while staging a handoff, only thinking settings are carried and an explicit diagnostic is written.

## Configuration and operation
- Configuration is in `.agents/memory/project-context.json` or the project root. Keys include `autoConsolidate`, `autoLearn`, `archiveEnabled`, `handoffEnabled`, `maxTokens`, `maxOutputTokens`, `maxMemoryChars`, `consolidateTurns`/`consolidateIntervalMs`, `autolearnTurns`/`autolearnIntervalMs`, `handoffKeepTokens`, `handoffAdaptive`, `handoffThresholdRatio`, `handoffTargetTokens`, `handoffLanguage`.
- Auxiliary models honor configured provider/model and otherwise use the authorized session model; unresolved routes warn once per process. Empty `provider`/`model` means the session model is used, so a Codex quota/auth failure hits consolidation and autolearn directly.
- `session_shutdown` always performs a forced silent consolidation; `agent_settled` consolidation is conditional and fire-and-forget.
- `--no-project-context` disables project-context features for a run.

## Repository and release conventions
- Release procedure: commit, annotated tag, push tag and `master` to both remotes, bump the pin in the separate `pi-config` repository, verify installed tagged blobs, run a real settings-installed probe, record evidence, then commit release documentation separately (the release-evidence commit lands on `master` after the tag; the tag stays on the release commit).
- Memory render changes are tracked and normally committed as `docs(memory): refresh the memory render`, separate from code commits.
- Directory-shaped extensions are installed only through pi packages (`pi install <source>@<ref>`); never copy them into `~/.pi/agent/extensions` (duplicate registration) and never add a `package.json` (pi's `extensions/` convention replaces npm install).
- Threshold, cap and budget tests pin exact numeric values plus label/summarize strings, so mutating a constant or letting auto accept a fixed-mode ratio fails a test.
- Full suite currently 12/12 (including `call-policy-test.mjs`, `memory-budget-test.mjs`, `memory-ops-test.mjs`, `sync-test.mjs`); `git diff --check` kept clean.
